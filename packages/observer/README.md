# Запуск наблюдателя

F.2 и F.5: `createClaudeBackend` и `createCodexBackend` запускают CLI без shell и возвращают проверенный `ObserverOutput`, расход или причину отказа. Путь CLI разрешается до очистки окружения; можно передать абсолютный исполняемый файл и префикс аргументов для npm-обёртки Codex.

`model` задаётся обязательно, `effort` — явно, если он задан конфигурацией. В `builtins` Claude передаётся разрешённый список из допуска версии; по умолчанию список пуст. Авторизация проверяется перед первым вызовом и заново после ошибки авторизации. Codex проверяет версию и обновляет каталог модели при её изменении.

`execute({ input, signal })` принимает JSON и необязательный сигнал отмены. `status()` возвращает контрактный `ObserverState` и количество занятых процессов; `subscribe()` сообщает изменения. `process_stuck` удерживает слот и запрещает следующие вызовы backend. Позднее подтверждение остановки освобождает слот; потеря Windows-лаунчера без файла статуса требует перезапуска. Состояние и уведомления предназначены для `/api/status` и SSE в G.4–G.6: этих маршрутов и подключения наблюдателя в текущем демоне ещё нет.

`createProcessRunner` — общая операция запуска для наблюдателя, чата, допуска, проб и проверки авторизации. На Unix она завершает группу процессов и ждёт `ESRCH`; на Windows использует переданный абсолютный `windowsLauncher` (`aang-hook.exe`, режим D.9). Закрытие каналов само по себе остановку не подтверждает. Проверка остановки длится 10 секунд, затем возвращает `process_stuck` и продолжает ждать подтверждения. Вывод процесса ограничен 16 MiB.

Рабочий каталог — `os.tmpdir()/aang-observer/empty`; `temporaryDirectory` позволяет задать корень временных файлов. Непустой каталог и инструкции `CLAUDE.md`/`AGENTS.md` в его предках, включая физический путь, запрещают запуск. Файлы входного профиля Codex удаляются после подтверждения остановки.

Это примитивы запуска, а не допуск реальных версий CLI: автоматический допуск и пробы относятся к F.6, планирование вызовов — к F.9, интеграция в демон — к G.6. Включение наблюдателя на Windows остаётся зависимым от отчёта D.8 и допуска F.6. Тесты используют только CLI из testkit и внешние обёртки процессов. Зомби проверяется нативным тестовым помощником на C (требуется `cc` на macOS/Linux); продуктовый код остаётся TypeScript и существующий Go-лаунчер.
