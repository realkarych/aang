# Демон

## Наблюдатель

Демон собирает наблюдателя из пакета `observer` (G.6, ADR-0007).

- **Backend.** При старте создаются backend `claude` и `codex`. Путь CLI задают `cli.claude` и `cli.codex`; без них CLI ищется в `PATH` окружения, с которым запущен демон. Модель, effort и таймаут — `observer.models`, `observer.effort` и `observer.timeoutMs`. Окружение CLI очищает `observer` (ADR-0007, ADR-0013). На Windows лаунчер — `aang-hook.exe`, который `aang install` кладёт в `AANG_HOME/bin`; без него backend выключен (`launcher_unavailable`).
- **Допуск.** Демон допускает оба backend на синтетическом входе (F.6) и только после этого запускает планировщик: так планировщик продолжает с сохранённого состояния восстановления (F.9), а не сбрасывает его допуском. Пока допуск идёт, факты копятся в `pending`. Результат допуска — `AANG_HOME/support/<runtime>-observer.json`.
  - Встроенные MCP-серверы, плагины и скиллы Claude, которые разрешены в `init`, по ADR-0007 берутся из матрицы поддержки. Матрицы ещё нет (R.5a, F.10), поэтому список пуст, и версия Claude, которая сообщает в `init` встроенные плагины, допуск не проходит (`disabled: isolation`).
  - Версий Claude с локальным контрактным прогоном пока нет (F.10), поэтому допущенный Claude работает с пометкой «изоляция от сообщений других сессий на этой версии не проверена» (решение владельца 5).
- **Новая версия CLI.** Рабочий вызов, который обнаружил другую версию, выключает backend (`version_not_admitted`), и демон допускает новую версию. Пока у backend идут вызовы старой версии, допуск откладывается и повторяется раз в секунду. После нарушения изоляции, при отсутствии CLI и после неудачного допуска демон сам допуск не повторяет: backend выключен до перезапуска демона.
- **Планировщик.** Он получает `observer.backend`, `observer.crossVendor` и `observer.budgetTokensPerHour`. Прогон идёт к backend вендора своей корневой сессии, если `observer.backend` его не переопределяет. Факты сессий другого вендора без `observer.crossVendor` наблюдателю не отправляются: они получают `not_interpreted`, а у прогона открывается пробел `cross_vendor_excluded`. После каждой принятой порции приём будит планировщик; остальные вызовы планируют его таймеры.
- **Остановка.** Сначала останавливается приём, затем наблюдатель: идущий допуск и вызовы отменяются, их порции возвращаются в `pending` без траты попытки. Ошибка наблюдателя, например нечитаемое сохранённое состояние восстановления, останавливает демон с ошибкой, как и ошибка приёма.

Состояние наблюдателя в `/api/status` и SSE подключается после G.4 и G.5. Предел входа `observer.inputLimitTokens` и каталог конфигурации Claude для контекста прогона планировщик получает с F.7b.

Тесты (`test/observer.test.ts`) запускают демон с поддельными `claude` и `codex` из `testkit`, путь к которым записан в конфиг. На Windows из одного пути запускается только `codex` — в раскладке npm-пакета (`codex.cmd` и `node_modules/@openai/codex/bin/codex.js`), которую находит `observer`; поддельный `claude` там требует `node` со скриптом, поэтому тесты Claude-backend идут на macOS и Linux. Поддельный `claude` в этих тестах не сообщает встроенных плагинов (`builtinPlugins: []`), потому что матрицы поддержки ещё нет. Привязку Codex-сессии к Claude-прогону тест делает через `engine` при остановленном демоне: API привязок появится в G.8.
