# Веб-интерфейс

React-приложение, которое демон раздаёт как статику с того же origin (ADR-0011). `pnpm build` собирает его Vite в `dist/`; пакет `aang` находит каталог через `import.meta.resolve('@aang/web')`, который указывает на `dist/index.html`. Код `web` обращается к демону только через API и SSE и импортирует из `contract` схемы ответов.

## Оболочка (H.1)

- **Вход.** Страницу открывает только cookie из одноразовой ссылки `aang open` (ADR-0003). Если любой запрос получил 401 — токен заменён или cookie устарела, — приложение показывает экран «Вход не выполнен» с подсказкой про `aang open`.
- **Адрес.** Список прогонов — `/`, прогон — `/?run=<id>`. Демон отдаёт `index.html` только на `/`, поэтому прогон передаётся параметром, а не путём.
- **Список прогонов** — `GET /api/runs`: состояние, цель или время начала, внимание, свежесть, режим поддержки, сессии, агенты, последнее событие. Пустой список объясняет охват: `watch --all`, отслеживаемые каталоги или их отсутствие.
- **Страница прогона** берёт снимок `GET /api/runs/:run` и подписывается на `GET /api/stream?run=` с `Last-Event-ID`, равным `change_seq` снимка. Поток читается через `fetch`, а не `EventSource`, потому что первый запрос уже несёт `Last-Event-ID`.
  - События `run`, `facts`, `model` и `attention` применяются к снимку: сводка и вид заменяются, объекты наблюдения, факты плана, сущности модели и пункты внимания обновляются по `id`, удалённые агенты убираются. Позиция — `id` последнего события.
  - Обрыв потока — переподключение с последней позицией и паузой 0,25–4 с.
  - `reset` — снимок перечитывается, подписка начинается с его `change_seq`.
  - 404 потока — снимок перечитывается. 404 снимка — «Прогон не найден»; снимок перечитывается раз в секунду, и страница возвращается, когда прогон появится снова.
- **Полоса состояния** — панель ламп над содержимым. Лампа горит жёлтым (внимание) или красным (сбой) и всегда несёт значок и подпись (RFC §5). Лампа с подробностями — кнопка, которая раскрывает список под панелью.

| Лампа | Откуда | Горит |
| --- | --- | --- |
| Связь | опрос `/api/status`, состояние потока | нет связи с демоном, переподключение, прогон не найден |
| Наблюдатель | `observer` сводки прогона; на списке — `observer.backends` статуса или прогоны | отставание, повтор, недоступен, отключён |
| Модель (прогон) | `observer.last_success_at` и очередь фактов | модель не строилась при ждущих фактах или нерабочем наблюдателе, отставание от 30 с |
| Режим (прогон) | `support_modes` и сессии прогона | «только файлы», «только hooks» |
| Hooks | `runtimes` статуса | hooks не активны в сессиях, не установлены, не доверены, двойная регистрация |
| Источники | пробелы статуса и прогона: потеря источника, ошибка чтения, неизвестная раскладка, изменение после `prune`; на списке — прогоны с потерянным источником | есть такие пробелы |
| Записи | `unknown_records` статуса или сессий прогона | есть нераспознанные записи |
| Spool | `spool` и пробелы spool статуса | превышен порог, остановлен `aang stop`, нет аренды, файлы отброшены по сроку |
| Версии | `versions` статуса, если они есть | версии без полной поддержки |
| Не наблюдаемо | `not_observable` статуса, если есть | всегда |

## Вид до смысла (H.2)

Этапы строит только наблюдатель (ADR-0006). До его первого ответа и при недоступном LLM страница прогона показывает объекты наблюдения и факты плана из того же снимка и потока, без интерпретации.

- **Внимание** — полоса под шапкой прогона: открытые пункты (`resolution: open`). Сначала пункты, по которым рантайм ждёт человека (`runtime_wait: active`), затем по возрасту — это правила 1 и 3 порядка ADR-0008; правило 2 (зависимые этапы) и объяснение порядка добавит H.3. У пункта — вид значком и подписью, «ждёт ответа», текст, сессия и агент из связанного вопроса или действия, время открытия и автор («по правилу aang» или «от наблюдателя»). Текст длиннее четырёх строк свёрнут, кнопка «Показать полностью» раскрывает его.
- **Сессии и агенты** — трасса прогона:
  - сессия: короткий id, поверхность и версия рантайма, каталог, ветка, запуски, выполнение, свежесть (`события идут`, `нет новых событий`, `источник потерян`, `hooks не активны`), режим поддержки и время последнего события;
  - дерево агентов по `parent`: основной агент, субагенты и teammates с типом и описанием, служебные — с подписью вида;
  - шаги агента по времени: действия (исход или выполнение, инструмент, ввод) и вопросы (решение человека, вид, текст). Решение, которое aang вывел по последующим событиям, а не увидел, подписано основанием («интерпретация aang»), как и такой же исход действия. Текст вопроса показан одной строкой и раскрывается целиком кнопкой «Показать полностью». Видны последние шесть шагов и все идущие; ранние раскрываются кнопкой. Ввод действия — команда, путь, шаблон, URL или промпт и описание — читается лениво из факта начала действия `GET /api/facts/:id`; неудачное чтение повторяется не раньше чем через 5 с, пока шаг на экране или при следующем его открытии. Действия, унаследованные форком, помечены.
- **План решателя** — факты `plan_update` от новых к старым: источник, сессия и агент, время, текст плана и пункты со статусом значком и подписью, пометка «формат записи не проверен» для форматов без эталонной сессии.

Состояние везде показано цветом вместе со значком и подписью (RFC §5); для успешного действия подпись скрыта визуально и остаётся для чтения с экрана.

## Ограничения текущей версии

- Событий `status` в потоке и потока без `run` у демона пока нет (G.5). Поэтому статус и список прогонов перечитываются раз в 2 с; событие `status` клиент принимает, но полосу состояния обновляет опрос.
- Наблюдатель в демон ещё не подключён (G.6), версии и режимы «не наблюдаемо» не заполняются (G.7). Лампы для них отображают данные, как только демон их отдаст.
- Порядок зоны внимания, отметки просмотра и снятия пунктов из `view.zone` и `attention.views` демон пока не заполняет (M.8); зона использует их в H.3.
- Вложенность действий code mode Codex в ячейку `exec` не раскрывается: шаги идут плоско по времени.
