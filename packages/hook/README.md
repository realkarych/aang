# Установка hooks

`installCodexHooks` принимает `aangHome`, `hookBinarySource`, `codexHome` и `codex: { command, args? }`. Команда CLI и профиль задаются явно. `args` позволяет запускать скрипт CLI через Node без shell. `timeoutMs` ограничивает один опрос app-server; по умолчанию — 10 секунд.

Установка удерживает блокировку `hooks.json` на время двух опросов `hooks/list` и записи файла. Каждый опрос запускает отдельный stdio-процесс с `CODEX_HOME` и рабочим каталогом, равными `codexHome`: `initialize` → уведомление `initialized` → `hooks/list`. После ответа или ошибки процесс завершается. Операции с тредами и ответы на запросы сервера отсутствуют.

Чужие записи сопоставляются по позиционному `key`. Изменение их `trustStatus`, исчезновение записи или ошибка итогового опроса отменяют установку. Откат восстанавливает исходные байты и права `hooks.json`, сохраняет симлинк либо удаляет файл, созданный установкой. Если файл успела изменить другая программа, её правка сохраняется: ошибка `hooks_file_changed` указывает резервную копию для восстановления после проверки. Откат касается регистрации; скопированный бинарь в `AANG_HOME/bin` остаётся. `config.toml` и `hooks.state` установщик не пишет.

`codexHooksState({ aangHome, codexHome, codex, timeoutMs?, signal? })` — статическая проверка для CLI и демона. `signal` отменяет проверку: app-server останавливается, функция завершается ошибкой `codex_app_server`. Результат или ошибка отдаются после того, как группа процессов app-server опустела (ADR-0013). Подтверждение ждётся не дольше 10 с после команды остановки: ответа, ошибки, таймаута, отмены или выхода процесса. Без подтверждения проверка завершается ошибкой `codex_app_server`, и следующие опросы того же `codexHome` в этом процессе app-server не запускают, пока остановка не подтвердится. Записью текущей установки считается только запись с командой, которую пишет `installCodexHooks` для этого `aangHome`: `<AANG_HOME>/bin/aang-hook codex user <spool>` с теми же кавычками (`codexHookCommand`; на Windows — форма PowerShell, раздел «Windows»). Функция возвращает эти записи (`hooks`), остальные записи aang (`stale`), предупреждения рантайма и `status`:

| Значение | Состояние |
| --- | --- |
| `not_installed` | Записей текущей установки нет |
| `untrusted` | Хотя бы одна запись текущей установки не имеет `trustStatus: trusted` |
| `inactive` | Все записи текущей установки доверены, но хотя бы одна выключена |
| `active` | Все записи текущей установки доверены и включены |

`stale` — записи `aang hook` или `aang-hook` с другой командой: прежние установки, другой `AANG_HOME`, правка вручную. На `status` они не влияют, поэтому доверенные записи прежней установки не дают ложного `active` (D.6, раздел 2). Установка нейтрализует их на месте, как и раньше.

Ошибка запуска, таймаут, некорректный ответ или ошибки загрузки hooks приводят к `HookInstallError` с причиной `codex_app_server`; они не подменяются состоянием «не установлено». `active` описывает конфигурацию. Наличие событий от конкретной сессии проверяет динамическая диагностика из ADR-0004.

## Windows

- **Команда записи.** Codex исполняет команду hook через PowerShell, поэтому `codexHookCommand` на Windows даёт `& '<AANG_HOME>\bin\aang-hook.exe' 'codex' 'user' '<AANG_HOME>\spool'`: оператор вызова `&`, пути в одинарных кавычках, одинарная кавычка удваивается. Нейтрализованные записи получают команду `exit 0`, потому что `true` в PowerShell — не команда. Записи aang в обеих формах распознаются на любой ОС.
- **app-server через лаунчер.** На Windows app-server запускается через лаунчер `aang-hook launch` в режиме `stream` (ADR-0013, техническое решение 4, принято владельцем 2026-10-07). Лаунчер держит все процессы CLI в Job Object и передаёт CLI свой stdin по мере поступления. По закрытию stdin он завершает задание и пишет файл статуса.
  - Обычный режим лаунчера закрывает вход CLI после первых n байт, а app-server Codex на закрытый вход завершается, не ответив на `hooks/list`.
  - Результат или ошибка отдаются после файла статуса, то есть после подтверждения, что задание опустело. Лаунчер, который не смог запустить CLI, пишет в статус шаг и ошибку, и они попадают в сообщение `codex_app_server`.
  - Зависший лаунчер не держит вызов: через 10 с после команды остановки без файла статуса опрос завершается ошибкой, а поздний файл статуса снимает запрет на следующие опросы. Лаунчер, вышедший без файла статуса, даёт ошибку сразу, и запрет держится до перезапуска процесса.
- **Какой бинарь — лаунчер.** Для `codexHooksState` — копия бинаря в `<AANG_HOME>\bin`, для `installCodexHooks` — `hookBinarySource`. Без лаунчера проверка завершается ошибкой `codex_app_server`, и CLI не запускается.
- **Команда Codex.** Команда без пути ищется в `PATH` как `codex.com` или `codex.exe`: так её нашёл бы Node без shell. npm-шим `codex.cmd` лаунчер не запускает, поэтому для npm-установки нужен путь к настоящему `codex.exe` или `node` со скриптом пакета в `args`.
- **Когда что ставится.** Установку по умолчанию на Windows выбирает `cli`: `aang install` без флагов ставит только плагин Claude, hooks Codex — только с `--codex` (ADR-0013, решение 7). Функции этого пакета на Windows работают так же, как на macOS и Linux.

Побочные эффекты app-server в штатном `~/.codex` проверил D.6 (`docs/research/d6-app-server-live.md`). Процесс при старте сам обращается к сервисам OpenAI от имени пользователя и пишет логи и кэши в `CODEX_HOME`. Поэтому по ADR-0004 эти функции вызываются только по событию: установка и удаление, `status`, `doctor`, старт демона, изменение `hooks.json` или `config.toml`. Периодического опроса нет.

`aang install` для Codex (G.12) вызывает `installCodexHooks` и `codexHooksState` для профиля из конфига aang, `CODEX_HOME` или штатного `~/.codex`. Условия ADR-0004 после D.6 соблюдены: каждый процесс app-server завершается сразу после ответа `hooks/list`, а сама установка и есть событие, по которому идёт проверка. Одна установка запускает три коротких процесса: два опроса trust вокруг записи `hooks.json` и итоговую проверку состояния. `aang uninstall` app-server не запускает.

Интеграционные тесты используют временные профили и поддельный app-server и идут на трёх ОС, на Windows — через лаунчер. Строка команды проверяется запуском через shell Codex: `sh` на macOS и Linux, `pwsh -NoProfile -Command` на Windows. Тесты прав файлов и симлинков идут только на macOS и Linux. Установку и проверку с настоящим `codex` из CI проверяет контрактный тест демона (`AANG_ISOLATION_CODEX`).
