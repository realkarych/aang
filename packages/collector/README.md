# Collector

При создании `createCollector` параметр `openGaps` принимает сохранённые открытые пробелы. Сборщик восстанавливает из них поиск потерянных потоков (`source_lost`), сохраняя ключ, детали и время обнаружения эпизода. При восстановлении источника возвращает закрытие того же пробела через `CollectorBatch.gaps`.

При перезапуске вызывающая сторона передаёт открытые пробелы через `openGaps`, а сохранённые курсоры — через `start(cursors)`. Если курсор потерянного потока уже заменён курсором другого потока по тому же пути, поиск всё равно продолжается по `StreamKey` во всех корнях рантаймов. Найденный поток перечитывается независимо от `lookback`.

Курсоры и обновления пробелов сохраняются вместе с принимаемой порцией до её подтверждения. Пример интеграции с настоящим хранилищем — `packages/daemon/test/collector-recovery.test.ts`.

`CollectorService.requestAttachment(path, stream)` ставит в очередь чтение текстового вывода Claude из `persistedOutputPath`. Вызывающая сторона запрашивает вложения после определения охвата сессии. Путь должен быть абсолютным и вести в `tool-results` внутри настроенного `<claude>/projects`; выход через символическую ссылку за этот корень не допускается.

Вложение приходит через `start()` как `CollectedRecord` канала `transcript`, с переданным потоком, позицией `file` и SHA-256 исходных байтов. Текст UTF-8 сохраняется целиком, включая BOM и переводы строк; пустой файл допустим. Двоичные данные, некорректный UTF-8, каталоги и ошибки чтения повторяются с паузой и при затяжной неудаче дают `read_failed`. Успешное чтение закрывает тот же пробел. `close()` отменяет ожидающие повторы.

Файлы `tool-results` читаются только по запросу, независимо от расширения. Одновременные одинаковые запросы объединяются; повторный запрос после выдачи читает файл заново. Дедупликацию по пути и хешу выполняет обычный приём в хранилище. `ack()` исходный файл не удаляет. Очередь запросов находится в памяти: после перезапуска вызывающая сторона повторяет запросы по сохранённым фактам, для которых ещё нет сырого снимка. Открытые `read_failed` вложений из `openGaps` сами чтения не запускают; повторный запрос с тем же путём и потоком продолжает сохранённый эпизод: новая ошибка не меняет `detected_at`, успешное чтение закрывает пробел. Сохранение через настоящий `engine` и доступ после удаления источника проверяет `packages/engine/test/attachments.test.ts`.

Корни рантаймов (`<claude>/projects`, `<claude>/sessions`, `<claude>/teams`, `<codex>/sessions`, `<codex>/archived_sessions`) в свежем профиле появляются только с первой сессией. Пока корня нет, сборщик держит нерекурсивный fs watch на ближайшем существующем родителе корня. Когда в родителе появляется следующий по пути к корню каталог, watch переходит на него. Появившийся корень сразу получает свой watch и обход, поэтому файлы первой сессии читаются за секунды, а не через обход раз в минуту (ADR-0004, решение 15). Наличие корня проверяется и при каждом обходе: пропавший корень снова ждут через родителя. С `collector.fsWatch: false` остаётся только обход. Тесты — `test/roots.test.ts` и приём через настоящий демон в `packages/daemon/test/ingest.test.ts`.

На macOS fs watch начинает сообщать об изменениях не в момент открытия: libuv запускает поток FSEvents асинхронно, и изменения, сделанные до его запуска, не приходят. Каталог, созданный в первые миллисекунды после открытия watch родителя, иначе не заметили бы ни проверка, ни watch, и первая сессия ждала бы обхода раз в минуту. Поэтому через секунду после открытия любого watch сборщик повторяет то, что watch заменяет: watch родителя снова проверяет следующий каталог на пути к корню, watch корня запрашивает обход, watch spool — перечисление. Демон с watch, который пропускает изменения первых полсекунды (`packages/daemon/test/late-watch.ts`), проверяет `packages/daemon/test/ingest.test.ts`.

Дописанные строки транскриптов и rollout сборщик находит по fs watch, по полному обходу корней и по проверке активных файлов. Раз в секунду он проверяет по `stat` файлы хвоста, изменённые за последние 10 минут, и читает их новые строки, не перечисляя каталоги. Поэтому строки, дописанные через дескриптор, который писатель держит открытым, читаются за секунду и на macOS, где FSEvents о такой записи не сообщает. Изменённым считается и файл со старым `mtime`, рост или подмену которого сборщик заметил за последние 10 минут: на Windows время записи открытого файла гарантированно обновляется только при закрытии дескриптора. Файл, простоявший дольше 10 минут, возвращается в проверку после обхода или чтения по событию watch (ADR-0004, решение 14). Приём такого rollout настоящим демоном проверяет `packages/daemon/test/ingest.test.ts`.

Снимки JSON-файлов (реестр, `*.meta.json`, `workflows/*.json`, `teams/*/config.json`) обход находит по отпечатку `(dev, ino, размер, mtime)`. Метки времени файловых систем грубые: тик NTFS (по умолчанию 15,6 мс), jiffy Linux, 2 с у FAT. Перезапись того же размера в пределах одного тика отпечаток не меняет, а уведомление о ней может потеряться, например при переполнении буфера `ReadDirectoryChangesW`. Поэтому если в момент чтения `mtime` файла моложе двух секунд, отпечатку ещё не доверяют: первый обход после того, как `mtime` станет старше двух секунд, перечитывает файл один раз. Такое чтение увидит любую запись из того же тика, а более поздняя запись получит другой `mtime`. То же содержимое повторно не выдаётся.

## Перечитывание и границы удаления

`rescan(streams, lookbackDays)` перечитывает с начала файлы перечисленных потоков. Со сроком перечитываются только файлы, изменённые в его пределах: так `aang watch` перечитывает ранее отброшенные потоки (ADR-0004). Без срока перечитываются все файлы потоков, как при перечитывании отстающего файла по запросу `engine`. Повторные запросы одного потока до обработки объединяются: запрос без срока важнее, иначе берётся больший срок.

`CollectorService.backfill(lookbackDays)` при следующем обходе корней читает с начала файлы без курсора, изменённые в пределах переданного срока. Это файлы, которые пропустил общий `lookback`. Сам общий срок не меняется: старые файлы, появившиеся позже, не читаются.

Границы удаления (`PruneBoundary`, ADR-0005) передаются на старте через `prunedStreams` и во время работы через `CollectorService.prune(boundaries)`. Для границы Claude демон считает хеш префикса функцией `prefixHash(path, offset)`, сборщик сравнивает его той же функцией.

- Claude: сборщик сравнивает хеш префикса до смещения границы при любом чтении файла потока с начала (бэкфилл, `rescan`, перенос, смена inode). При продолжении с курсора — тоже, если с последней проверки у файла изменились dev, inode, размер или время изменения: так видна перезапись файла на месте, в том числе пока сборщик был остановлен.
  - Совпал — чтение идёт со смещения границы, нумерация строк продолжает исходную. Курсор выдаётся, даже если новых строк нет.
  - Не совпал или файл короче — записей нет, курсор сбрасывается на начало файла. Выдаётся пробел `stream_changed_after_prune`, один раз на поток; открытый пробел из `openGaps` повторно не выдаётся. Остановленный файл перепроверяется, только когда меняются его dev, inode, размер или время изменения.
  - Новая граница того же потока заменяет прежнюю, снимает остановку и перечитывает остановленные файлы с начала. Прежний пробел хранилище удаляет вместе с прогоном, поэтому сборщик его забывает.
- Codex: при любом чтении потока с границей пропускаются строки с ordinal не больше `last_ordinal`. Строка без ordinal наследует последний встреченный, а до первого — пропускается.

`CollectorService.paused(work)` выполняет `work`, пока сборщик стоит между порциями: текущее чтение закончено, выданную порцию потребитель вернул следующим вызовом `next()`, новое чтение до конца `work` не начинается. Паузы выполняются по очереди. Демон удаляет прогон и передаёт границы внутри паузы, поэтому порция, прочитанная до границ, не попадает в приём после удаления.
