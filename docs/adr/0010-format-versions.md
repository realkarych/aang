# ADR-0010: Нестабильные форматы и версии

Статус: принято владельцем 2026-10-01. Записи TUI в CI вместо ручного чек-листа TUI Claude на Linux (решение 4) одобрены владельцем 2026-10-08.

## Контекст

Обе документации называют форматы транскриптов и rollout внутренними. Между версиями меняются типы записей и поведение usage; в Codex уже есть флаги сжатия и миграции rollout. Desktop и SDK встраивают собственные версии движков: Claude 2.1.284 при CLI 2.1.286, Codex SDK 0.159.3 при CLI 0.159.2 (спайк, разделы 1, 4, 5.2-F). После спайка Codex CLI у владельца обновился до 0.159.3.

RFC §7 разрешает объявлять поддержку только для конкретной версии и способа запуска после проверки: событий инструментов, дочерних агентов, usage, продолжения, сжатия и переподключения. Каждая обязательная поверхность должна проходить оба пользовательских сценария. Неизвестные записи сохраняются, пробелы видны в UI. Если Desktop не проходит, это ограничение выносится на решение владельца (RFC §4).

## Решение

### Терпимые парсеры

- Адаптер — набор парсеров по ключу `(рантайм, канал, тип записи)`. Это схемы `zod`, которые пропускают неизвестные поля.
- Неизвестный тип или поле не прерывает приём: сырая запись сохраняется всегда (ADR-0005), а неразобранная получает `parse_state=unknown`. UI показывает счётчик «непознанные записи» по сессии.
- Варианты разбора по версиям заводятся только там, где поведение действительно различается. Различие определяется по наличию записей, а не по номеру версии. Пример — usage Codex без `token_usage_record` (ADR-0009).
- Неизвестная раскладка файлов (например, сжатый или мигрированный rollout) распознаётся как непознанный поток и отмечается пробелом.
- Версия определяется по потоку:
  - Claude — поле `version` записей и `AI_AGENT` в окружении hook;
  - Codex — `session_meta.cli_version`;
  - Desktop и SDK — по версии встроенного движка и переменным окружения SDK.

### Эталонные сессии

- **Сценарии** (спайк, раздел 13.3):
  - события инструментов;
  - субагент и параллельные агенты;
  - usage;
  - resume;
  - сжатие;
  - fork;
  - план;
  - запрос одобрения и решение по нему;
  - явный вопрос;
  - прерывание;
  - переподключение: перезапуск демона во время сессии;
  - потеря источника: удаление, перенос, archive.
- **Запись.** Dev-инструмент `tools/record` запускает настоящие CLI во временном проекте с регистратором hooks через `--plugin-dir` (Claude) и обезличивает результат по правилам приложения A спайка, включая домашние пути Windows.
  - Регистратор — настоящий `aang-hook` во временный spool с действующей арендой: без аренды он молча ничего не пишет (ADR-0004).
  - Запись идёт на той ОС, для которой предназначена; WSL записью Windows не считается.
  - Codex-сценарии с hooks (hooks, субагенты, fork, TUI) пишутся с заглушкой Responses API во временном `CODEX_HOME`. Сценарий с реальной моделью пишется без hooks, в штатном home с `--ignore-user-config`: копия авторизации во временный home запрещена (спайк, раздел 13.1).
  - Движки Desktop записываются в режиме эмуляции (спайк, раздел 11).
- **Хранение:** `fixtures/sessions/<рантайм>/<версия движка>/<поверхность>/<ОС>/<сценарий>/` с манифестом:
  - версии, поверхность и ОС записи (`macos`, `linux`, `windows`), которую `tools/record` ставит сам;
  - шаги;
  - ожидаемые ключевые факты;
  - контрольные события с ожидаемым изменением карты для замера свежести: предикат над моделью или описание для разметчика (ADR-0007).

### Контрактные тесты

- **Адаптеры.** Адаптеры и движок объектов прогоняются по эталонным сессиям. Проверяются:
  - снимок нормализованных фактов и объектов;
  - отсутствие дублей фактов;
  - разрешённые связи;
  - инварианты usage — например, сумма `token_usage_record` треда равна последнему `thread_token_usage`, кроме форков: их счётчик наследует родителя;
  - отсутствие `unknown` среди покрытых типов.

  Тесты идут в CI на каждой ОС по записям всех ОС: это проверяет переносимость разбора, но не поддержку ОС, на которой запись не сделана.
- **Изоляция наблюдателя на каждой поддерживаемой версии CLI (одобрено владельцем).**
  - Codex — на заглушке Responses API, без авторизации: пустые `body.tools` и `input[additional_tools].tools`, попытки вызова получают `unsupported`, `--ephemeral` ничего не пишет, контрольный hook не исполняется при `--disable hooks` и исполняется без него; в обеих ветках одинаковый тестовый bypass доверия (ADR-0007). Тест идёт в CI с установленным CLI.
  - Claude — на установленном CLI, локально (нужна авторизация): автоматический допуск ADR-0007 плюс проверка `crossSessionInbound` сессией-пиром, которая отправляет наблюдателю сообщение.

  Результат записывается в матрицу поддержки.
- **Новая версия CLI у пользователя.** Перед рабочими вызовами демон выполняет автоматический допуск ADR-0007 на синтетическом входе. Без него наблюдатель на этой версии выключен. До локального контрактного прогона версия Claude используется с пометкой (ADR-0007, решение 7).

### Объявление поддержки

- Матрица `support/matrix.json` в репозитории. Ключ строки — `(рантайм, поверхность, ОС, размещение, версия движка)`.
  - Поверхности: Claude CLI, Claude Desktop (Local и worktree), Claude Agent SDK, Codex TUI, Codex `exec`, Codex Desktop (Local и worktree), Codex SDK.
  - ОС — macOS, Linux, Windows. Поддержка на одной ОС на другую не переносится (ADR-0013).
  - Размещение — локально, Docker, VM, SSH-режим Desktop, где применимо. Docker на любой ОС хоста — это ОС Linux; SSH-режим Desktop и VM относятся к ОС удалённой машины.
  - Для Desktop и SDK ключом служит версия встроенного движка, версия приложения хранится справочно.
  - В строке хранятся результаты обоих пользовательских сценариев, resume, сжатия, дочерних сессий и переподключения, а также результат допуска наблюдателя.
- Статусы:
  - `full`;
  - `limited` с перечнем пробелов;
  - `unverified`.
- Для `full` или `limited` нужны:
  - контрактные тесты по всем сценариям выше на записях этой ОС; записи другой ОС не засчитываются;
  - E2E-сценарии 1 и 4 (ADR-0012) на эталонных сессиях этой поверхности и ОС;
  - для размещения, отличного от локального, — проверка размещения (план, Q.1); эталонные записи берутся по ОС;
  - для Desktop — ручной чек-лист владельца (спайк, раздел 11) на каждой ОС, где проверяется Desktop; для интерактивного TUI Claude — чек-лист a–h (спайк, раздел 6) на macOS и Windows. Записи движка Desktop в эмуляции ручной допуск не заменяют.
  - для интерактивного TUI Claude на Linux достаточно записей TUI в CI (сценарии `teammates` и `input-dialogs` через `expect`), ручной чек-лист не нужен (одобрено владельцем 2026-10-08).
- Если Desktop не проходит оба сценария, ограничение выносится владельцу, а не исключается молча.
- Поддержка объявляется по точной версии движка. Непроверенная версия работает в терпимом режиме; UI показывает её в полосе состояния, без тревожной пометки на каждой сессии.
- `aang doctor` перечисляет встреченные версии и их статус. Появление новой версии — сигнал записать для неё эталонные сессии.

### Текущее состояние версий

- Матрица начинается пустой: до контрактных тестов все строки `unverified`, и наличие адаптера поддержкой не считается.
- Спайк проверял Codex CLI 0.159.2, Codex SDK 0.159.3 со своим бинарём и встроенную в Desktop сборку 0.159.2. У владельца Codex CLI уже 0.159.3. Данные спайка по 0.159.2 — образцы формата для разработки адаптеров, а не свидетельство поддержки 0.159.3. Совпадение номера с SDK тоже ничего не доказывает: SDK и CLI — разные поверхности со своими сборками.
- Первые эталонные сессии пишутся на версиях, установленных на момент записи (план, R.4): сейчас это Claude 2.1.286 (CLI, SDK), движок Claude Desktop, Codex CLI 0.159.3, Codex SDK 0.159.3 и сборка Codex Desktop. Они пишутся на каждой ОС MVP для поверхностей, которые на ней доступны.
- Профиль Codex-наблюдателя и замеры спайка относятся к 0.159.2. На 0.159.3 каталог модели перегенерируется, и наблюдатель используется только после допуска версии (ADR-0007). Новых экспериментов это решение не требует: проверку выполняют допуск и контрактный прогон.

## Последствия

- Каждая новая версия рантайма требует записи и прогона эталонных сессий. Это постоянная стоимость сопровождения: Claude выпускает патчи почти ежедневно.
- Обновление формата не ломает сбор: в худшем случае растёт число непознанных записей, а после исправления парсера их разбирает `aang reparse`.

## Решения владельца

Принято владельцем 2026-10-01:

1. Эталонные сессии записываются для каждой новой версии движка, встреченной в окружении владельца.
2. Бюджет записи с реальной моделью — около $1–2 на рантайм и версию.
3. Записанные инструментом и обезличенные эталонные сессии считаются сгенерированным кодом. Лимит размера PR в проекте отменён владельцем; PR остаются логически цельными (AGENTS.md).

Принято владельцем 2026-10-08 по отчёту Q.1 (`docs/research/q1-surface-matrix.md`, раздел 6, п. 5; PR #160):

4. Для интерактивного TUI Claude на Linux достаточно записей TUI в CI, ручной чек-лист не нужен. Чек-лист a–h остаётся на macOS и Windows.
