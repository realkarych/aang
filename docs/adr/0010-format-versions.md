# ADR-0010: Нестабильные форматы и версии

Статус: предложено 2026-10-01. Одобрен владельцем 2026-10-01 один пункт, помеченный в тексте: контрактные тесты изоляции наблюдателя на каждой поддерживаемой версии.

## Контекст

Обе документации называют форматы транскриптов и rollout внутренними. Между версиями меняются типы записей и поведение usage; в Codex уже есть флаги сжатия и миграции rollout. Desktop и SDK встраивают собственные версии движков: Claude 2.1.284 при CLI 2.1.286, Codex SDK 0.159.3 при CLI 0.159.2 (спайк, разделы 1, 4, 5.2-F).

RFC §7 разрешает объявлять поддержку только для конкретной версии и способа запуска после проверки: событий инструментов, дочерних агентов, usage, продолжения, сжатия и переподключения. Каждая обязательная поверхность должна проходить оба пользовательских сценария. Неизвестные записи сохраняются, пробелы видны в UI. Если Desktop не проходит, это ограничение выносится на решение владельца (RFC §4).

## Решение

### Терпимые парсеры

- Адаптер — набор парсеров по ключу `(рантайм, канал, тип записи)`. Это схемы `zod`, которые пропускают неизвестные поля.
- Неизвестный тип или поле не прерывает приём: сырая запись сохраняется всегда (ADR-0005), а неразобранная получает `parse_state=unknown`. UI показывает счётчик «непознанные записи» по сессии.
- Варианты разбора по версиям заводятся только там, где поведение действительно различается. Различие определяется по наличию записей, а не по номеру версии. Пример — usage Codex без `token_usage_record` (ADR-0009).
- Неизвестная раскладка файлов (например, сжатый или мигрированный rollout) распознаётся как непознанный поток и отмечается пробелом.
- Версия определяется по потоку:
  - Claude — поле `version` записей и `AI_AGENT` в окружении hook;
  - Codex — `session_meta.cli_version`;
  - Desktop и SDK — по версии встроенного движка и переменным окружения SDK.

### Эталонные сессии

- **Сценарии** (спайк, раздел 13.3):
  - события инструментов;
  - субагент и параллельные агенты;
  - usage;
  - resume;
  - сжатие;
  - fork;
  - план;
  - запрос одобрения и решение по нему;
  - явный вопрос;
  - прерывание;
  - переподключение: перезапуск демона во время сессии;
  - потеря источника: удаление, перенос, archive.
- **Запись.** Dev-инструмент `tools/record` запускает настоящие CLI во временном проекте с регистратором hooks через `--plugin-dir` (Claude) и обезличивает результат по правилам приложения A спайка.
  - Codex-сценарии с hooks (hooks, субагенты, fork, TUI) пишутся с заглушкой Responses API во временном `CODEX_HOME`. Сценарий с реальной моделью пишется без hooks, в штатном home с `--ignore-user-config`: копия авторизации во временный home запрещена (спайк, раздел 13.1).
  - Движки Desktop записываются в режиме эмуляции (спайк, раздел 11).
- **Хранение:** `fixtures/sessions/<рантайм>/<версия движка>/<поверхность>/<сценарий>/` с манифестом:
  - версии и поверхность;
  - шаги;
  - ожидаемые ключевые факты;
  - контрольные события с полем `expect_map_change` для замера свежести (ADR-0007).

### Контрактные тесты

- **Адаптеры.** Адаптеры и движок объектов прогоняются по эталонным сессиям. Проверяются:
  - снимок нормализованных фактов и объектов;
  - отсутствие дублей фактов;
  - разрешённые связи;
  - инварианты usage — например, сумма `token_usage_record` треда равна последнему `thread_token_usage`, кроме форков: их счётчик наследует родителя;
  - отсутствие `unknown` среди покрытых типов.

  Тесты идут в CI.
- **Изоляция наблюдателя на каждой поддерживаемой версии CLI (одобрено владельцем).**
  - Codex — на заглушке Responses API, без авторизации: пустые `body.tools` и `input[additional_tools].tools`, попытки вызова получают `unsupported`, `--ephemeral` ничего не пишет, hooks не исполняются. Тест идёт в CI с установленным CLI.
  - Claude — на установленном CLI, локально (нужна авторизация): `init` (инструменты, MCP, плагины), действие `crossSessionInbound`, отсутствие транскрипта.

  Результат записывается в матрицу поддержки.
- **Новая версия CLI у пользователя.** Перед включением наблюдателя демон выполняет на ней те же проверки изоляции автоматически (ADR-0007). Без успешной проверки наблюдатель на этой версии выключен.

### Объявление поддержки

- Матрица `support/matrix.json` в репозитории. Ключ строки — `(рантайм, поверхность, среда, версия движка)`.
  - Среда — локально, Docker, VM, SSH-режим Desktop.
  - Для Desktop и SDK ключом служит версия встроенного движка, версия приложения хранится справочно.
- Статусы:
  - `full`;
  - `limited` с перечнем пробелов;
  - `unverified`.
- Для `full` или `limited` нужны:
  - контрактные тесты по всем сценариям выше;
  - E2E-сценарии 1 и 4 (ADR-0012) на эталонных сессиях этой поверхности;
  - для Desktop — ручной чек-лист владельца (спайк, раздел 11), для интерактивного TUI Claude — чек-лист a–h (спайк, раздел 6).
- Если Desktop не проходит оба сценария, ограничение выносится владельцу, а не исключается молча.
- Поддержка объявляется по точной версии движка. Непроверенная версия работает в терпимом режиме; UI показывает её в полосе состояния, без тревожной пометки на каждой сессии.
- `aang doctor` перечисляет встреченные версии и их статус. Появление новой версии — сигнал записать для неё эталонные сессии.

## Последствия

- Каждая новая версия рантайма требует записи и прогона эталонных сессий. Это постоянная стоимость сопровождения: Claude выпускает патчи почти ежедневно.
- Обновление формата не ломает сбор: в худшем случае растёт число непознанных записей, а после исправления парсера их разбирает `aang reparse`.

## Открытые вопросы владельцу

1. Когда записывать эталонные сессии. → для каждой новой версии движка, встреченной в окружении владельца; инструмент записи автоматизирует это.
2. Бюджет записи с реальной моделью. → около $1–2 на рантайм и версию, как в спайке.
3. Лимит PR в 400 строк по AGENTS.md включает фикстуры, а записанные эталонные сессии — это сотни строк JSONL. → изменить AGENTS.md: записанные инструментом и обезличенные эталонные сессии приравнять к сгенерированному коду, если в PR с ними нет кода. До изменения записи делятся на PR по сценариям.
