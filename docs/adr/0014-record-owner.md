# ADR-0014: Владелец собранной записи

Статус: принято владельцем 2026-10-02.

## Контекст

Приём E.1 должен сохранять неизвестные и неразобранные записи сессий в охвате (ADR-0005), определять охват по первому `cwd` корневой сессии и исключать наблюдателя (ADR-0004). Факты из `parse` недостаточны: при `unknown` и `invalid` их нет, хотя запись может называть сессию. Форматы рантаймов знает адаптер; `engine` не должен разбирать их самостоятельно.

Основание: [PR #25](https://github.com/realkarych/aang/pull/25), предварительный контракт для E.1 и замечание 3 к его кросс-ревью. Владелец явно одобрил ADR-0014 в сессии исправлений PR #25 от 2026-10-02. Этот ADR дополняет интерфейс адаптера из ADR-0011.

## Решение

Добавить в `Adapter` обязательный чистый метод `owner(record: CollectedRecord): RecordOwner | null`. Он определяет владельца независимо от результата `parse`, не выполняет I/O и не принимает решение об охвате.

| Поле `RecordOwner` | Значение |
| --- | --- |
| `session: SessionKey` | Корневая сессия, которой принадлежит запись |
| `thread: 'root' \| 'agent'` | Запись потока корня либо агента, включая служебный тред |
| `cwd: string \| null` | Непустой каталог, указанный этой записью; это не готовое решение об охвате |
| `start: boolean` | Запись явно открывает корневую сессию; если указан `cwd`, это её начальный каталог |
| `observer: boolean` | В записи или заголовке spool есть распознанный маркер наблюдателя |

`null` означает, что адаптер не смог установить владельца записи. Ошибки вспомогательных полей не уничтожают известную идентичность. `cwd`, признаки начала и наблюдателя извлекаются независимо: нераспознанное свидетельство даёт `null` или `false`, корректные соседние поля сохраняются. `observer: false` означает отсутствие распознанного маркера в этой записи, а не доказательство, что сессия не принадлежит наблюдателю. `start: true` допустим при `cwd: null`.

### Источники свидетельств

- Hooks обоих рантаймов: сессия из `session_id`, поток агента из `agent_id`, каталог из `cwd`. `SessionStart` с `source` `startup`, `clear` или `fork` открывает корневую сессию; `resume` и `compact` продолжают прежнюю. Запись агента не открывает корневую сессию. Маркеры spool: `CLAUDE_CODE_ENTRYPOINT=aang-observer` и `CODEX_INTERNAL_ORIGINATOR_OVERRIDE=aang_observer`.
- Строки транскрипта Claude: `sessionId`, `agentId`, `cwd`, маркер `entrypoint: aang-observer`. Строка сама не объявляет начало сессии: первую строку корня с каталогом при чтении файла с начала определяет `engine` по позиции.
- Файлы Claude: владелец meta-файла агента, снимка workflow и строки журнала workflow определяется по пути; владелец конфига команды — по `leadSessionId`. Удалённый конфиг команды без payload не даёт владельца.
- Rollout Codex: корневая сессия и тред определяются по ключу потока. `session_meta` корневого треда открывает сессию; `session_meta` и `turn_context` могут назвать каталог. Маркеры в `session_meta`: `thread_source: aang-observer` или `originator: aang_observer`. Ошибка одного поля не стирает корректный каталог или другой маркер.

### Граница ответственности

`engine` получает адаптеры через реестр, решает охват и сохраняет его рядом с курсором по ADR-0004 и ADR-0011. Он отличает начальный каталог корня от текущего каталога hook и каталога агента, учитывает общий git-каталог worktree и отбрасывает сессии наблюдателя. Владение не зависит от наличия фактов: неизвестные и неразобранные записи известной сессии в охвате сохраняются сырыми по ADR-0005. Этот PR не реализует транзакцию приёма E.1.

## Альтернатива

Поле владельца во всех вариантах `ParseResult` связало бы извлечение идентичности с разбором фактов и потребовало изменения всех точек возврата `parse`. Отдельный метод сохраняет существующий протокол разбора; цена решения — дополнительный разбор payload при приёме.

## Проверка

Интеграционные тесты вызывают публичные API настоящих адаптеров на образцах рантаймов. Они проверяют владельца, корень и агента, начало сессии, каталог, самоисключение и сочетания корректных и некорректных полей. Транзакцию приёма и решение охвата проверяют первые потребители в E.1.
