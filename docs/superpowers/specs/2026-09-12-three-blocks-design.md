# Три блока: спутник, который читается за три секунды

**Дата:** 2026-09-12. **Заменяет** разделы «Вьюер», «Ячейки», «Вердикт», «Таймлайн», «Окрестность»,
«Шапка» спеки `2026-09-11-live-companion-design.md`; хук, установка и Codex из неё остаются в силе, кроме
того, что сказано в «Что уходит».

## Зачем

Вьюер после первой итерации отвечает на пятнадцать вопросов одновременно: шесть строк метаданных, девять
счётчиков, предупреждения, таймлайн на сто ходов, одиннадцать фильтров, входящее с бейджами и детальная
панель с шестью кнопками. Пользователь читает его как многостраничный ответ модели, и главная задача —
вернуться после паузы и за три секунды понять, что решено, что висит и что отвергнуто, — не решается.

Установленные факты о сценарии:

- **Момент:** возвращение после паузы. Вопрос: «что тут решили без меня и на чём остановились».
- **Экран:** треть–половина экрана ноутбука во встроенном браузере десктоп-приложения Claude / Codex,
  то есть колонка 450–750 px. Двух панелей не бывает.
- **Действие:** никакого. aang — среда только для чтения; ответы агенту даются словами в чате, агент сам
  переписывает карту следующим `/aang`.

## Требования

- **R1. Три блока.** Вся карта — три блока друг под другом: **Решено**, **Под вопросом**, **Отвергнуто**.
  Никаких других разделов, ячеек, вкладок, панелей.
- **R2. Одна строка на узел.** Строка = глиф, глагол, текст, метка темы. Текст обрезается на второй строке.
  Ни одного бейджа в строке. Клик раскрывает под строкой подробности.
- **R3. Темы.** Каждый узел принадлежит теме — короткому имени, которое пишет модель. Тема проходит через
  все три блока и служит единственной связью между ними в списке.
- **R4. Вид темы.** Клик по метке темы показывает только её узлы, в тех же трёх полосах, с нарисованными
  рёбрами между ними. Это единственная графовая картинка, и она никогда не больше одной темы.
- **R5. «Новое».** Строка, появившаяся после прошлого визита, отмечена тонкой полоской слева. Прошлый визит
  помнит браузер; сервер ничего не пишет.
- **R6. Подвал.** Одна строка внизу: на сколько ходов карта отстаёт от транскрипта; при неустановленном
  хуке — как его поставить. Больше никаких метаданных на странице.
- **R7. Живое обновление** через SSE сохраняется: раскрытые строки и текущий вид темы переживают
  перерисовку.
- **R8. Ничего не пишется.** Сервер отвечает только на `GET`. Вердикты, «видел», outbox, `seen_at`
  удаляются из сервера, хука, скилла и схемы.
- **R9. Экспорт** читается так же, как экран: три раздела, внутри — темы.

## Данные

### Новое поле узла: `topic`

`topic: string | null` — тема в 1–3 словах, в нижнем регистре, без точки («размер PR», «модели»,
«вьюер»). Пишет модель в `/aang`; `merge` берёт её из кандидата как контентное поле (`CONTENT_FIELDS`),
так что на повторном запуске тему можно переименовать. Валидатор: строка не длиннее 40 символов или
`null`. Одно и то же имя = одна тема; сравнение после `strip()` и `casefold()`.

Правило для модели (в SKILL.md): тема отвечает на «о какой части работы это было», а не «какого рода это
узел». Узлы, связанные рёбрами, почти всегда одной темы; если модель даёт им разные — это сигнал
проверить ребро. Тем в карте обычно 3–7; больше десяти — темы слишком мелкие.

### Удаляется: `seen_at`

Из схемы, `normalize`, `STAMP_FIELDS` (остаётся `("added_at",)`), README и SKILL.md. Старые карты с
`seen_at` в файле: `normalize` молча отбрасывает поле; `merge` записывает карту без него.

### Блоки (производные)

Модуль `src/aang/blocks.py` заменяет `triage.py` целиком (файл `triage.py` удаляется вместе с
`CELLS`, `cell`, `is_unseen`, `VERDICTS`, `apply_verdict`).

```
BLOCKS = (
    ("decided",  "Решено",       "в силе — выбрано или принято молча"),
    ("open",     "Под вопросом", "ждёт вас: предложено агентом, спрошено, отложено"),
    ("rejected", "Отвергнуто",   "остаётся в записи, чтобы не предлагать снова"),
)
```

`block(node)` — первое совпавшее правило:

| условие | блок |
|---|---|
| `status == "rejected"` | `rejected` |
| `status == "superseded"` | `None` — в списке не показывается (см. «Заменённые») |
| `kind == "open"` | `open` |
| `status == "proposed"` | `open` |
| `triage` задан | `open` |
| иначе (`accepted`: decision или tacit) | `decided` |

### Строка (производная, `line(node)`)

Возвращает `(glyph, verb, text)`:

| узел | глиф | глагол | текст |
|---|---|---|---|
| decision · accepted | `●` | «решили» | `decision` |
| tacit | `◌` | «молча» | `decision` |
| decision · proposed · agent | `◆` | «агент сам» | `decision` |
| decision · proposed · user, без triage | `◇` | «предложено» | `decision` |
| любой · triage research | `?` | «изучить» | `decision`, для open — `question` |
| любой · triage discuss | `?` | «обсудить» | то же |
| open без triage | `○` | «открыто» | `question` |
| decision · rejected | `✖` | «отвергнуто» | `decision` |
| decision · superseded | `●` зачёркнуто | «заменено» | `decision` |

Глагол — одно слово-состояние, не полное предложение; текст — поле узла как есть. Триаж старше
остального: узел под ресерчем показывается как «изучить», кем бы он ни был предложен.

### Темы (производные, `topics(nodes)`)

Вход — узлы карты в порядке списка. Выход — список тем в порядке показа, каждая
`{"name": str, "ids": [..]}`:

1. Узлы с непустым `topic` группируются по нормализованному имени.
2. Узлы без `topic` собираются в компоненты связности по рёбрам `relates` и `superseded_by`
   (в обе стороны). Компонента, в которой хотя бы один узел имеет `topic`, присоединяется к этой теме
   (при нескольких разных — к теме самого раннего по списку узла с темой). Компонента без единой темы
   получает имя из первых трёх слов `question` самого раннего узла, с многоточием, если слов больше.
3. Порядок тем — по убыванию максимального `added_at` среди узлов темы; при равенстве — по позиции
   самого позднего узла в списке. Тема, в которую узел пришёл последним, наверху.

Внутри блока строки идут группами по темам в этом же порядке; внутри группы — новые сверху (обратный
порядок списка). Тема, представленная в блоке одной строкой, всё равно показывает метку — метка и есть
связь с другими блоками.

Одна и та же функция живёт в `src/aang/blocks.py` (для экспорта) и в `ui/model.js` (для экрана); тест
в `tests/test_server.py` прогоняет обе на одной карте-фикстуре и сравнивает результат, как сейчас
сравниваются ячейки.

### Заменённые

Узел со `status: superseded` не имеет блока. Он показывается в раскрытии узла, на который указывает его
`superseded_by`: строка «заменило: ~~старый текст~~» с возможностью раскрыть старый узел целиком. Цепочка
замен раскрывается рекурсивно. В виде темы заменённые видны как полноценные узлы в полосе Решено,
зачёркнутые, с ребром «заменено на» к преемнику: там история и есть содержание.

## `/api/map`

`annotate` меняется так:

- на каждом узле вместо `cell` — `block` (строка или `null`) и `topic` (имя темы после разрешения по
  правилам выше, всегда строка);
- добавляется верхнеуровневый `topics` — результат `topics(nodes)`;
- `tail` (список ходов) удаляется; остаётся `coverage` (`covered_to`, `turns`) — подвалу этого хватает;
- `hook`, `root`, `errors`, `warnings`, `transcript_error` остаются; `warnings` экран не показывает
  (они для `aang check`), но клиенты API их получают как прежде.

Маршруты `POST /api/node/<id>/verdict` и `POST /api/node/<id>/seen`, `_mutate`, `_post_verdict`,
`_post_seen` и `do_POST` целиком удаляются; на `POST` отвечает стандартный `BaseHTTPRequestHandler`
(501). `GET /api/events` и `Watcher` остаются как есть.

## Хук, сессия, скилл

- `hook.py`: убирается чтение outbox из `UserPromptSubmit` (`_after`, `VERDICT_WORDS`, блок вердиктов
  в `prompt_context`). Дейксис по id и строка покрытия остаются. Stop-nudge не меняется.
- `session.py`: `outbox_append/read/clear` и `OUTBOX_FILE` удаляются. `cli.py`: подсказка про
  `.gitignore` больше не упоминает `outbox.jsonl`; корневой `.gitignore` проекта — тоже.
- `SKILL.md`: шаг 0 (outbox) удаляется; абзац «те же четыре вердикта приходят из вьюера» удаляется;
  запрет писать `seen_at` удаляется; добавляется поле `topic` с правилом выше и одной строкой в
  «Пачка в конце шага»: вердикт пользователь даёт словами в чате, и только так.
- `README.md`: раздел «Live» переписывается под три блока; таблица файлов без `outbox.jsonl`; пример
  узла без `seen_at`, с `topic`.

## Экран

### Список (вид по умолчанию)

```
┌──────────────────────────────────────────────┐
│ Решено                                   14  │
│ ▎● решили  PR < 400 строк вместе с тестами   │  размер PR
│  ● решили  субагенты только fable и opus     │  модели
│  ◌ молча   порт 8790 никто не выбирал        │  вьюер
│  …                                           │
│                                              │
│ Под вопросом                              8  │
│ ▎◆ агент сам  старый вьюер убит, новый на…   │  вьюер
│  ○ открыто  как подтверждать авторство при…  │  авторство
│  ? обсудить  одна карта на проект или на…    │  карта
│                                              │
│ Отвергнуто                                2  │
│  ✖ отвергнуто  sonnet для ревью              │  модели
│                                              │
│ карта отстаёт на 7 ходов                     │
└──────────────────────────────────────────────┘
```

- Заголовок блока: имя и число строк. Подзаголовок из `BLOCKS` — только как `title` при наведении.
- Цвет: у каждого блока свой приглушённый оттенок для глифа и левой границы группы (зелёный / янтарный /
  красный); текст везде одного цвета. Глиф и глагол — одним оттенком, текст — основным.
- Метка темы — справа, мелко, серым; на узком экране (< 520 px) переезжает под текст.
- Пустой блок показывает заголовок с нулём и одну строку «—». Пустая карта: одна фраза «карта пуста —
  запустите /aang».
- Никакого поиска, фильтров, счётчиков, таймлайна, окрестности, кнопок, легенды, шапки.

### Раскрытие строки

Под строкой, тем же шрифтом, поля подряд, каждое одной строкой с тихой подписью слева:

- вопрос (`question`) — только если он не совпадает с показанным текстом;
- почему (`why`); для tacit подпись «откуда»;
- против (`against`) — каждый пункт с отдельной строки;
- следствие (`consequence`);
- связи — одно предложение из `relates` и `related_by` с русскими метками (`REL_LABELS`), id
  кликабельны: клик прокручивает к строке и раскрывает её; id из другого блока работают так же;
- заменило: ~~текст~~ (см. «Заменённые»);
- цитата: первая цитата, ход и роль, текст цитаты; «не проверено» — единственная пометка на странице —
  когда `verified` ложно, с причиной из `reason` через `title`;
- триаж/автор: одна строка «предложил агент», «вы отправили изучить» и т. п., только если это не
  очевидно из глагола.

Пустые поля пропускаются. Раскрытых строк может быть несколько. Раскрытие хранится в состоянии по id и
переживает живое обновление; узел, исчезнувший из карты, забывается.

### Вид темы (R4)

Клик по метке темы. Страница заменяется на:

```
← все темы        вьюер · 5 узлов

Решено
  [● порт 8790 никто не выбирал]      [● вьюер читает файлы сам]
        └─────── держится на ────────────────┘
Под вопросом
  [◆ старый вьюер убит, новый поднят]
        └─ осиротело ─┐
Отвергнуто
  [✖ второй порт для второй сессии]
```

- Три горизонтальные полосы в том же порядке и цветах, что блоки списка. Узел — плашка с глифом и
  текстом в одну строку (обрезка на 40 символах, полный текст в `title`); ширина полосы — ширина окна,
  плашки переносятся на следующий ряд, если не помещаются.
- Рёбра — SVG-линии поверх полос между центрами плашек, с подписью посередине: «держится на»,
  «осиротело», «обесценило», «заменено на». Направление — от узла, на котором записана связь, к цели;
  стрелка на конце. Рёбра к узлам другой темы не рисуются; вместо них у плашки маленькая пометка
  «+N вне темы».
- Заменённые узлы видны зачёркнутыми в полосе Решено с ребром «заменено на».
- Клик по плашке раскрывает узел под полосами (то же раскрытие, что в списке). «← все темы» и `Esc`
  возвращают список с сохранённым раскрытием.
- Раскладка — чистая функция `topicLayout(nodes, width)` в `ui/model.js`: позиции плашек по рядам и
  список рёбер с координатами; тест проверяет, что все узлы темы получили позицию, что ребро
  соединяет правильные плашки, и что на ширине 450 px ни одна плашка не выходит за край.

### «Новое» (R5)

`localStorage["aang:visit:" + root + ":" + session_id]` хранит ISO-время последнего визита. При загрузке
страницы значение читается в `state.since` и **не меняется до перезагрузки**; записывается текущее время
при `visibilitychange → hidden` и `pagehide`. Строка новая, если `added_at > state.since`. При первом
визите (`since` пуст) полосок нет. Обращения к `localStorage` завёрнуты в try/catch: без хранилища
страница просто не помечает новое.

### Подвал (R6)

Одна строка мелким шрифтом, всегда последняя:

- `coverage.covered_to` и `turns` есть: «карта отстаёт на N ходов» при N > 0, «карта покрывает всю
  сессию» при N = 0; при `covered_to: null` — «карта ещё ничего не покрывает»;
- `transcript_error`: «транскрипт не найден: <причина>» вместо покрытия;
- `hook.installed` ложно: добавляется « · хук не установлен: `aang install`»;
- `errors` непусто: вместо всей страницы — «карта невалидна» и список ошибок; это единственный случай,
  когда на экране список ошибок.

`hook.last_event_at`, `session_id`, `transcript_path`, `generated_at`, `warnings` на экране не
показываются.

### Живое обновление (R7)

SSE как сейчас. Перерисовка полная, состояние (`expanded: Set<id>`, `topic: name | null`, `since`)
переживает её. Если открытая тема исчезла из карты, вид возвращается к списку. Прокрутка сохраняется
браузером; страница не прокручивает пользователя к новому.

## Экспорт (R9)

`export_markdown` группирует по `BLOCKS` (три `##`), внутри — `###` по темам в порядке `topics()`,
под темой — узлы как сейчас (`_node_markdown`), новые сверху. Заменённые узлы печатаются внутри своей
темы в разделе Решено, зачёркнутые, как раньше. Темы из fallback-компонент печатаются под их
вычисленным именем. Шапка экспорта не меняется.

## Что уходит

`triage.py`, `VERDICTS`, `apply_verdict`, `is_unseen`, ячейки, `seen_at`, `POST`-маршруты, `_mutate`,
outbox (сервер, сессия, хук, скилл, README, `.gitignore`), таймлайн, окрестность, фильтры, поиск,
счётчики, шапка, легенда, кнопки вердиктов, «видел», «скопировать ссылку», хвост сессии в UI, строка

`model.js`. Тесты этих вещей удаляются вместе с ними.

Не трогаем: хук (кроме outbox), `install`, Codex-адаптер, `merge`, `check`, `TranscriptSource`,
`Watcher`, `/api/events`, `/model.js`.

- `tests/test_hook.py`: промпт без outbox; при наличии старого `outbox.jsonl` файл игнорируется.
- `tests/test_store.py`: экспорт по трём блокам и темам; `topic` переживает merge как контент.

## Процесс проверки восприятия

После реализации — не меньше двух итераций «анализ → правка → полное ревью», каждая субагентом на fable:
ревьюер открывает вьюер через Playwright на ширине 560 px с картой этой сессии, делает скриншоты списка,
раскрытия и вида темы и отвечает на три вопроса: (1) за три секунды видно ли, что решено / что висит /
что отвергнуто; (2) есть ли на экране хоть один элемент, который не отвечает ни на один из этих вопросов;
(3) читается ли вид темы без объяснений. Всё, что не проходит, чинится следующим субагентом, и
ревью повторяется. Итерации заканчиваются, когда ревьюер не находит ничего по пунктам 1–2.

## Ограничения

- Python 3.9, только стандартная библиотека; UI — один HTML и один JS без зависимостей.
- Каждый PR < 400 добавленных строк вместе с тестами; PR, состоящий из удалений, считается по
  добавленным строкам. Никаких строчных комментариев; docstrings разрешены.
- Субагенты — только fable и opus.

## Риски

- **Модель не проставит `topic`.** Fallback по компонентам даёт группировку, но имена «первые три слова
  вопроса» слабее. Экран это переживает; SKILL.md делает тему обязательной частью узла.
- **Слишком много тем.** Десять тем на двадцать узлов превращают метки в шум. Правило «3–7 тем» в
  SKILL.md и мягкая проверка `aang check` (замечание, когда тем больше десяти и половина из них с одним
  узлом) — в этой итерации только замечание.
- **Вид темы на большой теме.** Тема на 15 узлов в трёх полосах с рёбрами внахлёст. Плашки переносятся
  рядами, рёбра рисуются как есть; если это не читается, следующая итерация — свёртка цепочек замен в
  одну плашку. Не решаем сейчас.
