# aang — живой спутник сессии: realtime, триаж, обратная связь, Codex

Дата: 2026-09-11. Статус: согласовано с пользователем по секциям, план не написан.
Базовые спеки: `docs/spec.md` (R1–R8) и `2026-09-11-map-relations-and-search-design.md` (U1–U10)
остаются в силе. Эта спека добавляет, не отменяет.

## Зачем

Образ результата, сформулированный пользователем: рядом с сессией Claude Code или Codex, где
запущен `/aang`, открыт UI, который обновляется сам и показывает все решения — принятые
пользователем, принятые агентом, и то, что агент выдал пачкой в конце длинного шага («решил A,
обрати внимание на X, запусти Z, проверь, правильно ли ABC»). Цель — кратно снизить нагрузку на
вспоминание хода сессии, последних решений агента и собственных решений.

Сегодня инструмент до этого не дотягивает в пяти местах:

1. Карта обновляется только когда человек набрал `/aang`. Это уже записано на карте как открытый
   вопрос `o2` («кто зовёт /aang, если человек не догадался»).
2. Вьюер читает карту один раз при открытии и больше не меняется.
3. У решения нет автора: известна только роль каждой цитаты.
4. Пачка от агента никак не раскладывается: всё, что он «решил», попадает в `accepted` или
   `proposed`, «отвергнуто» и «под вопросом» на карте не существуют.
5. Codex не поддерживается: другой формат транскрипта, другой путь к сессиям, другой способ
   подключить скилл.

Граф решений исследован и отвергнут с измерениями (`.superpowers/ux/graph-feasibility.md`,
выжимка в спеке связей). Единственная стабильная раскладка — ход × вид при фиксированном
масштабе. Она здесь и строится — как таймлайн, не как граф.

## Факты, на которых стоит дизайн

- **Хуки обеих сред совпадают почти поле в поле.** Claude Code (`~/.claude/settings.json`) и
  Codex 0.154 (`~/.codex/hooks.json`, `[features] hooks = true` по умолчанию) вызывают команду на
  `SessionStart`, `UserPromptSubmit`, `Stop`; в stdin приходит JSON с `session_id`,
  `transcript_path`, `cwd`, `hook_event_name`; ответ `{"hookSpecificOutput":
  {"hookEventName": …, "additionalContext": "…"}}` подмешивает текст в контекст модели.
  Продолжить ход из `Stop`: Claude Code — `{"hookSpecificOutput": {"hookEventName": "Stop",
  "continueConversation": true, "continueReason": "…"}}`, Codex — `{"decision": "block",
  "reason": "…"}`. Claude Code дополнительно даёт в `Stop` поля `turn_number` и
  `stop_hook_active` — последний равен `true`, когда ход продолжается по требованию самого
  stop-хука, и `false` (или отсутствует) на обычной остановке; у Claude Code есть предохранитель:
  не больше 8 продолжений подряд на один промпт. У Codex поле то же и значит то же.
- **Транскрипт Codex**: `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-<ts>-<session_id>.jsonl`. Первая
  строка — `{"type": "session_meta", "payload": {"id": …, "cwd": …}}`. Реплики чисто читаются из
  `{"type": "event_msg", "payload": {"type": "item_completed", "item": {"type": "UserMessage" |
  "AgentMessage", "content": [{"type": "text" | "Text", "text": …}]}}}` — служебные вставки
  (`<environment_context>`) туда не попадают, они есть только в `response_item`.
- **Скиллы Codex** читаются из `$HOME/.agents/skills` и `<repo>/.agents/skills`, вызываются
  `$aang`; фронтматтера `disable-model-invocation` там нет.

## Требования

- **L1 Карта обновляется без человека.** Хук среды раз в N ходов заставляет модель в сессии
  переписать карту. Пишет по-прежнему модель с контекстом, не сторонний суммаризатор (основной
  архитектурный выбор `docs/spec.md` сохраняется).
- **L2 Вьюер живой.** Изменение карты или транскрипта видно во вьюере не позже чем через две
  секунды, без перезагрузки страницы, с сохранением выделения, прокрутки и открытых редакторов.
- **L3 Ход сессии виден одним взглядом.** Таймлайн: ось — номер хода, позиция узла — функция его
  данных, при росте ничего не переезжает (U9). Непокрытый хвост ходов виден как хвост.
- **L4 У решения есть автор.** `decided_by: user | agent` на каждом решении; претензия на
  авторство пользователя без его слов среди цитат — замечание проверки.
- **L5 Пачка от агента раскладывается по ячейкам.** Входящее / ресерч / обсудить / подтверждено /
  отвергнуто. Ячейка — производная от полей узла, не отдельная сущность.
- **L6 Вердикт из вьюера доходит до агента.** Действие во вьюере меняет карту сразу и попадает
  агенту в контекст на его следующем ходе. Без хука ничего не теряется: событие ждёт следующего
  ручного `/aang`.
- **L7 Дейксис.** Id узла в промпте пользователя разворачивается в содержимое узла.
- **L8 Одна реализация на две среды.** Хук, скилл, сервер, формат карты общие; различаются только
  адаптер транскрипта и место установки.
- **L9 Ничего не деградирует от использования.** По-прежнему: ни канваса, ни графовой
  библиотеки, ни сохранённых позиций (U10). Stdlib Python 3.9 (R7).
- **L10 Realtime не работает молча.** Если хук не установлен или давно не подавал сигнал, вьюер
  говорит об этом в шапке.

## Данные

### Поля узла

```json
{
  "id": "d9",
  "kind": "decision",
  "status": "proposed",
  "decided_by": "agent",
  "triage": null,
  "seen_at": null,
  "…": "остальные поля как раньше"
}
```

| поле | значения | кто пишет | что значит |
|---|---|---|---|
| `status` | `accepted` \| `proposed` \| `superseded` \| **`rejected`** | модель, вьюер | ADR-статус позиции. `rejected` — новое: предложение отвергнуто и остаётся записью (R5: следующая сессия видит, что уже отвергали). У `open` по-прежнему только `proposed`; `rejected` у `tacit` значит «пользователь не хотел этого значения» |
| `decided_by` | `user` \| `agent` | модель, вьюер | только у `decision`. Кто принял. У `tacit` и `open` поля нет (валидатор отвергает) |
| `triage` | `null` \| `research` \| `discuss` | модель, вьюер | «под вопросом»: требует ресерча / обсуждения. Имеет смысл у `decision` со `status: proposed` и у `open`; на `accepted`, `rejected`, `superseded` валидатор отвергает |
| `seen_at` | ISO-8601 UTC \| `null` \| отсутствует (то же, что `null`) | сервер | пользователь нажал «видел». `merge` сохраняет как `added_at`; экспорт не показывает; модель никогда не пишет, `merge` выкидывает из кандидата |
| `against` | как раньше | модель, вьюер | комментарий к «отвергнуть» из вьюера добавляется сюда строкой |

Совместимость: карта без новых полей валидна; `decided_by` отсутствует — «неизвестно», вьюер
показывает знак вопроса, не «агент»; `triage` отсутствует ⇔ `null`.

Проверка `decided_by` (замечание, не ошибка, как замечания про id в прозе): узел с
`decided_by: user`, у которого ни одна цитата не имеет `role: user`, получает
`△ узел d9: заявлено решение пользователя, но среди цитат нет его слов`. Причина — короткое «ок»
пользователя не проходит порог цитаты (t5), поэтому это замечание, а не отказ.

### Ячейки (производные)

Вьюер считает ячейку у каждого узла по правилу, в этом порядке, первое совпавшее:

| ячейка | правило |
|---|---|
| Отвергнуто | `status: rejected` |
| Ресерч | `triage: research` |
| Обсудить | `triage: discuss` |
| Подтверждено | `kind: decision`, `status: accepted` (внутри — пометка `decided_by`) |
| Входящее | `kind: decision`, `status: proposed`, `decided_by: agent`; либо `kind: open` без `triage`, ещё не просмотренный |
| Неявное / Осиротело / Висит | как раньше, для `tacit` и `open`, которые не попали выше |

Одна строка — одно место. Открытый узел без вердикта показывается во «Входящем», пока не
просмотрен (`seen_at` пуст или старше `added_at`); просмотренный — в «осиротело / висит». Так
«Входящее» остаётся тем, чего пользователь ещё не видел, и пустеет от использования.
Предложение агента (`proposed`, `decided_by: agent`) остаётся во «Входящем» и после «видел»:
оно ждёт вердикта, а не взгляда.

Сервер отдаёт ячейку как `cell` на каждом узле в `/api/map` (та же логика, что `related_by`:
считается в `annotate`, одна реализация для вьюера и экспорта). Экспорт группирует по ячейкам
поверх нынешних групп: сначала «Входящее», «Ресерч», «Обсудить», «Отвергнуто», затем как сейчас.

### Файлы в `.aang/`

| файл | пишет | читает | коммитится |
|---|---|---|---|
| `map.json` | `merge`, сервер | все | да |
| `candidate.json` | модель | `merge` | нет |
| `session.json` | хук | `merge`, `check`, `view`, хук | нет |
| `outbox.jsonl` | сервер | хук, скилл (ручной `/aang`) | нет |
| `config.json` | человек | хук | по желанию |

`session.json`:

```json
{"harness": "claude", "session_id": "7df13757-…", "transcript_path": "/Users/…/7df13757-….jsonl",
 "cwd": "/Users/x/proj", "last_nudge_turn": 42, "last_event_at": "2026-09-11T12:00:00Z"}
```

`harness` — `claude` | `codex`. `last_nudge_turn` — номер хода транскрипта (по индексу aang,
не `turn_number` среды), на котором хук в последний раз просил обновить карту. Файл пишется
атомарно (временный файл + `os.replace`), как `map.json`.

`outbox.jsonl`, по событию в строке:

```json
{"at": "2026-09-11T12:00:00Z", "kind": "confirmed", "node": "o3", "text": "Замеряем на этой машине: 5 заходов до и после"}
{"at": "…", "kind": "rejected", "node": "t3", "text": "субагенты должны быть на opus"}
{"at": "…", "kind": "research", "node": "d9", "text": ""}
{"at": "…", "kind": "discuss", "node": "o1", "text": ""}
```

`kind` ∈ `confirmed | rejected | research | discuss`. «Видел» в outbox не пишется.

При первом `merge`, если в `.gitignore` проекта нет строк для `candidate.json`, `session.json`,
`outbox.jsonl`, `merge` печатает предложение добавить их — не правит файл молча.

## Хук: `aang hook`

Одна команда, одна на обе среды. Читает JSON из stdin, по `hook_event_name` выбирает ветку. Всегда
выходит с кодом 0; при любой внутренней ошибке — молча (ошибка в stderr, stdout пуст), чтобы
поломка aang никогда не ломала сессию. Если в `cwd` (или его родителях до корня git) нет
`.aang/map.json` — ничего не делает: глобальная установка безопасна для проектов без карты.
Корень `.aang/` определяется как ближайший родитель `cwd` с `.aang/map.json`; так хук работает и
из worktree, если карта лежит в нём.

Среда определяется по полям: наличие `prompt_id` или `turn_number` — Claude Code; наличие
`turn_id` при отсутствии первых — Codex; иначе по `os.environ` (`CLAUDE_CODE_SESSION_ID`).
Определение среды влияет только на форму ответа из `Stop`.

**Все три события** пишут `session.json` (`harness`, `session_id`, `transcript_path`, `cwd`,
`last_event_at`), сохраняя `last_nudge_turn`.

**`SessionStart`**: только `session.json`. Контекст не подмешивает.

**`UserPromptSubmit`** собирает `additionalContext` из трёх частей, каждой — только если есть что
сказать, и молчит, если пусто:

1. *Outbox.* Если `outbox.jsonl` не пуст: блок

   ```
   Из вьюера aang с прошлого хода (обязательно отреагируй в ответе и учти при следующем
   обновлении карты):
   - отверг t3 «Какой моделью работают субагенты?»: «субагенты должны быть на opus»
   - подтвердил o3 ответом: «Замеряем на этой машине: 5 заходов до и после»
   - отправил d9 в ресерч
   ```

   Файл очищается **после** успешной записи ответа в stdout (усечение до нуля, не удаление).
2. *Дейксис.* Id вида `\b[dto]\d+\b` в `prompt`, **существующие в карте**, каждый — блок из
   `question`, `kind`, `status`, `decided_by`, `triage`, `decision`, `why`, `consequence`,
   `relates` и `related_by` (в словах: «держится на d7», «на этом держатся: o6»). Не больше пяти
   узлов за раз; больше — первые пять и строка «…и ещё N».
3. *Покрытие.* Одна строка «карта aang покрывает ходы до N из M» — только если хвост не пуст.

**`Stop`** решает, пора ли обновлять карту. Читает транскрипт через `session.json` (оттуда же,
куда только что записал `transcript_path`), индексирует, считает:

- `covered_to` — как в `annotate` (наибольший ход среди проверенных цитат);
- `user_turns_since` — число реплик пользователя после `covered_to`;
- `minutes_since` — от `generated_at` карты.

Просит обновить, когда **все** условия выполнены:

- `user_turns_since ≥ 5` **или** (`minutes_since ≥ 15` и `user_turns_since ≥ 1`);
- последний ход транскрипта `> last_nudge_turn` (не пинать дважды на одном месте);
- `stop_hook_active` не `true` — иначе это уже продолжение по хуку, и второй пинок зациклил бы
  сессию;
- `candidate.json` не существует (модель ещё в процессе прошлого обновления — не мешать).

Пороги читаются из `.aang/config.json` (`{"nudge_turns": 5, "nudge_minutes": 15}`), если файл
есть; иначе значения по умолчанию. Отдельной команды для настройки нет.

Ответ — продолжить ход с причиной (форма по среде, см. «Факты»). Текст причины:

```
aang: с последнего обновления карты прошло 6 твоих ходов с пользователем. Обнови карту сейчас:
выполни скилл aang (Claude Code: инструмент Skill, skill "aang"; Codex: $aang). Не спрашивай
разрешения — это плановое обновление. После обновления заверши ход как обычно.
```

Перед ответом `last_nudge_turn` записывается в `session.json`. Если модель не обновит карту,
следующий пинок будет только когда транскрипт вырастет — цикла нет.

Скилл `aang` в Claude Code теряет `disable-model-invocation: true`: иначе модель не сможет
выполнить его по пинку. Описание скилла остаётся строгим: «по `/aang` от пользователя или по
указанию хука aang; не по собственной инициативе».

## Вьюер

### Живое обновление

`GET /api/events` — `text/event-stream`. Сервер держит соединение; фоновый поток раз в секунду
сравнивает `(mtime, size)` трёх файлов: `map.json`, `session.json`, транскрипт из `session.json`
(или найденный по `session_id` карты). Изменение — событие `data: {"changed": ["map"]}`; раз в 30
секунд без событий — `: ping`. Клиент на `changed` перечитывает `/api/map` и перерисовывает,
сохраняя: выбранный узел, позицию прокрутки списка и таймлайна, открытый редактор с несохранённым
текстом (перерисовка его не трогает), фильтры и поисковую строку. Обрыв — `EventSource`
переподключается сам; шапка показывает «связь потеряна» через 5 секунд без соединения.

Собственные записи (вердикт, правка, «видел») возвращают карту в ответе, как сейчас; следующее
событие `changed` по этому же файлу клиент пропускает, если тело `/api/map` не изменилось с
последнего ответа (сравнение по хешу тела).

### Хвост сессии

`/api/map` получает `tail`: `[{"turn": 61, "role": "user", "text": "первые 200 символов"}, …]` —
ходы после `coverage.covered_to`; при пустом `covered_to` — пусто (нечего считать хвостом). Вьюер
показывает полосу «не на карте: 7 ходов, 3 ваших» под шапкой, раскрывающуюся списком; реплики
пользователя выделены.

### Ячейки в списке

Список над нынешними группами получает пять ячеек в порядке: Входящее, Ресерч, Обсудить,
Подтверждено, Отвергнуто; затем Неявное, Осиротело, Висит — по правилу из «Данные». Пустая ячейка
не рисуется, кроме «Входящего»: пустое «Входящее» — строка «ничего нового», это главный сигнал
вернувшемуся. Счётчики ячеек в шапке. Внутри ячейки порядок как сейчас: новейшие сверху.

В строке решения — маркер автора: «вы» / «агент» / «?». Фильтр «мои / агента» рядом с фильтрами
вида и статуса.

### Вердикт

В панели любого узла — одна группа кнопок: **подтвердить · в ресерч · обсудить · отвергнуть**, и
поле комментария (необязательное; для «подтвердить» открытого — обязательное: это ответ).
Кнопки, неприменимые к узлу, не рисуются: у `superseded` — ничего; у `rejected` — только
«подтвердить» (передумал); у `accepted` — «отвергнуть» и «обсудить».

`POST /api/node/<id>/verdict` с телом `{"verdict": "confirmed" | "rejected" | "research" |
"discuss", "text": "…"}`. Сервер под `write_lock`:

| вердикт | узел | изменение |
|---|---|---|
| confirmed | `open` | `kind: decision`, `decision: text`, `status: accepted`, `decided_by: user`, `triage: null` |
| confirmed | `tacit` | `kind: decision`, `status: accepted`, `decided_by: user` (значение остаётся) |
| confirmed | `decision` proposed/rejected | `status: accepted`, `decided_by: user`, `triage: null` |
| rejected | любой не-superseded | `status: rejected`, `triage: null`; `text` в `against` |
| research / discuss | `open`, `decision` proposed/accepted | `triage`; у `accepted` решения — `status: proposed` (подтверждённое снова под вопросом) |

Всегда: `hand_edited: true`, валидация, сохранение, строка в `outbox.jsonl`, ответ — карта.
Ошибка валидации — 422 с текстом, файл не тронут, outbox не пишется.

`POST /api/node/<id>/seen` — `seen_at: now`, без `hand_edited` (это не правка записи), без
outbox. Кнопка «видел» в строке и в панели; «видел всё во Входящем» в заголовке ячейки.

Кнопка «скопировать ссылку» в панели кладёт в буфер `d4 — Через сколько «ждёт ввода» перестаёт
требовать внимания?`.

### Таймлайн

SVG-лента между шапкой и списком, высота ~110 px, без библиотек.

- Ось x — номер хода; масштаб 12 px на ход, фиксированный; лента прокручивается по горизонтали.
  Ширина = `turns × 12` плюс левая колонка «без хода» (узлов без проверенной цитаты) 60 px.
- Три дорожки: неявное, открытое, решения (сверху вниз). Узел — маркер на ходе своей первой
  проверенной цитаты; несколько узлов на одном ходе и дорожке — лесенкой по 6 px вниз.
- Форма маркера — автор: залитый круг — `decided_by: user`, контур — `agent`, ромб — `tacit`,
  квадрат — `open`. Цвет — ячейка. Зачёркнутый (`superseded`) — серый с чертой; `rejected` —
  крест.
- Непросмотренный узел (`seen_at` пуст или старше `added_at`) — с кольцом; при появлении в живом
  обновлении кольцо один раз мигает.
- Граница покрытия — вертикальная линия на `covered_to`; хвост правее заштрихован, реплики
  пользователя в нём — засечки.
- Клик по маркеру = выбор узла (список и панель прокручиваются к нему). У выбранного узла на ленте
  рисуются дуги к соседям — только его (степень ≤ 5 на реальной карте). Наведение — подсказка с
  id и вопросом.
- Автопрокрутка к правому краю при обновлении — только если пользователь и так был у правого края
  (порог 40 px); иначе позиция сохраняется.
- Уже 900 px: три дорожки складываются в одну, вид кодируется формой; уже 600 px: лента скрыта,
  кнопка «показать ход сессии».

### Окрестность

В панели узла над списком связей — мини-граф: SVG ~ 320 × 180. Выбранный узел в центре; слева —
цели его исходящих рёбер (`rests_on`, `orphaned_by`, `moots`), справа — узлы, чьи рёбра ведут в
него (`related_by`); сверху `superseded_by`, снизу — те, кого он заменяет. Не больше шести
соседей; при переполнении — шестой заменяется на «+N», клик раскрывает список связей ниже.
Позиции: соседи в столбце по порядку в `nodes`, равномерно по высоте — без раскладки. Рёбра —
прямые с подписью отношения. Клик по соседу делает его центром (то же, что выбрать узел).
Узел без связей — «ни с чем не связано», мини-граф не рисуется.

## Codex

- **Адаптер.** `transcript.index(path)` определяет формат по первой непустой строке: объект с
  `"type": "session_meta"` — Codex; иначе — Claude Code, как сейчас. Формат Codex: ход — каждый
  `event_msg/item_completed` с `item.type ∈ {UserMessage, AgentMessage}`; текст — конкатенация
  `content[].text` по частям с `type` `text`/`Text`/`input_text`/`output_text`; роль
  `user`/`assistant`. Нумерация ходов, канонизация и поиск цитат — общие. Subagent-транскрипты
  Codex, если появятся в этой папке, отличаются по `session_meta.thread_source` и не считаются
  сессиями.
- **Поиск сессии.** `default_roots()` возвращает и `~/.claude/projects`, и `~/.codex/sessions`;
  `find_session` для Codex ищет `**/rollout-*-<session_id>.jsonl` (глубина `ГГГГ/ММ/ДД`), а
  «самый свежий» выбирается среди обоих деревьев; при равенстве по mtime приоритет у файла, чей
  `cwd` (Codex: `session_meta.cwd`; Claude: имя папки проекта) совпадает с `--root`. Флаг
  `--transcript-root` работает как раньше для обоих.
- **`session.json` первичен.** `merge`, `check`, `view` берут транскрипт из него, если файл есть и
  путь существует; `--session` / `--transcript` в командной строке перекрывают; поиск «самого
  свежего» — последний резерв. `merge` печатает, какой транскрипт взял и откуда узнал.
- **Скилл.** Один `SKILL.md`. README, Install: `ln -s ~/src/aang/.claude/skills/aang
  ~/.agents/skills/aang` рядом с нынешней строкой для `~/.claude/skills`. Из шага 6 процедуры
  уходит `--session "$CLAUDE_CODE_SESSION_ID"`; вместо него — `aang merge` без аргументов, и
  фраза: «сессию merge знает из `.aang/session.json`, который пишет хук; без хука он возьмёт самый
  свежий транскрипт и напечатает, какой». Шаг «прочитай `.aang/outbox.jsonl`, если он не пуст,
  учти вердикты, после merge очисти файл» добавляется перед написанием кандидата. Шаг 8 (`aang
  view`) не запускает второй сервер, если порт занят своим же `aang view` (ответ `/api/map` с
  тем же `root`): печатает существующий URL.
- **Скилл учит раскладывать пачку.** Раздел «Пачка в конце шага»: то, что агент решил сам —
  `decision`, `status: proposed`, `decided_by: agent`, не `accepted`, пока пользователь не
  согласился словами или действием; «обрати внимание на X», «запусти Z» — `open` с `orphaned_by`
  на решение, из которого следуют, и фразой в `why`, кому адресовано; «уточни, правильно ли ABC»
  — `open`, в `why` — что вопрос адресован пользователю. Вердикт, сказанный пользователем в чате
  («нет», «давай изучим», «обсудим потом», «да, так»), записывается в `status` / `triage` /
  `decided_by` при следующем обновлении; отвергнутое не удаляется — `rejected`.

## Установка: `aang install`

`aang install [--claude] [--codex] [--print]`. Без флагов — обе среды, для каждой — если её
каталог существует (`~/.claude`, `~/.codex`). Для каждой среды:

- Читает файл настроек (`~/.claude/settings.json` / `~/.codex/hooks.json`), при отсутствии —
  создаёт с пустым объектом.
- В `hooks.SessionStart`, `hooks.UserPromptSubmit`, `hooks.Stop` добавляет запись
  `{"hooks": [{"type": "command", "command": "<абсолютный путь к aang> hook", "timeout": 20}]}`
  (Claude Code — с `"matcher": "*"` там, где событие его принимает), если записи с командой,
  оканчивающейся на ` hook` и содержащей `aang`, ещё нет. Чужие записи не трогает.
- Пишет атомарно, сохраняя отступ 2 и Unicode; печатает, что добавил, что уже было.
- `--print` — только печатает результирующий JSON для каждой среды.

`aang install` не правит `config.toml` Codex: `[features] hooks` включён по умолчанию; если
хуки там выключены, `install` печатает предупреждение, прочитав `config.toml` (простая проверка
строки `hooks = false` под `[features]`).

Путь к `aang` в команде — тот, по которому запущен `install` (`sys.argv[0]`, разрешённый через
`os.path.realpath`), чтобы хук не зависел от `PATH` среды.

## Сценарии

1. **Возврат к сессии.** Открыл вьюер: во «Входящем» три предложения агента и два вопроса к вам,
   на таймлайне видно, что это последние 12 ходов, хвост — 4 хода. Нажали «в ресерч» на одном,
   «подтвердить» на двух, «отвергнуть» с комментарием на одном. Следующий ваш промпт агенту
   несёт все четыре вердикта; агент отвечает, что меняет, при следующем пинке карта отражает
   `rejected` и `accepted`.
2. **Долгий шаг агента.** Агент 20 минут работал и выдал пачку. Stop-хук видит 15 минут и новые
   ходы, просит обновить карту. Вьюер мигает пятью новыми маркерами на таймлайне, «Входящее»
   показывает 5.
3. **«Что с d4?»** Вы пишете «d4 ещё актуально?». Агент получает узел целиком, включая «на этом
   держится…» и «неактуально из-за d6», и отвечает по делу.
4. **Codex.** Та же сессия в Codex: `aang install --codex`, `$aang` в чате, дальше всё то же.
5. **Передача.** Следующий запуск `/aang` и свежий агент читают `status: rejected`,
   `decided_by`, `triage` — и не предлагают отвергнутое снова.

## Тесты

`unittest`, без зависимостей, как сейчас.

- `transcript`: фикстура Codex-транскрипта (session_meta + item_completed + response_item с
  environment_context, который **не** должен индексироваться); определение формата; поиск
  сессии по обоим деревьям, приоритет `cwd` при равном mtime.
- `schema`: `rejected`, `decided_by` только у decision, `triage` только у proposed/open,
  замечание про авторство без цитаты пользователя; нормализация старых карт.
- `store`: `merge` сохраняет `seen_at`, выкидывает `seen_at`/`related_by`/`cell` из кандидата,
  переносит `decided_by`/`triage`/`rejected`; экспорт с ячейками.
- `hook`: все три события × две среды; форма ответов; `session.json`; пинок при 5 ходах и при
  15 минутах, отсутствие пинка при `last_nudge_turn`, при `stop_hook_active: true`, при
  существующем `candidate.json`; outbox подмешивается и очищается только после вывода; дейксис
  только по существующим id, не больше пяти; отсутствие карты — пустой stdout, код 0; битый
  stdin — код 0.
- `server`: `annotate` считает `cell` и `tail`; вердикты (таблица выше) с проверкой карты и
  outbox; 422 без записи; `seen`; SSE — изменение файла даёт событие в пределах 2 секунд; чужой
  `Origin` на новых POST — 403.
- `install`: пустой файл, файл с чужими хуками (сохраняются), повторный запуск (без дубликатов),
  `--print` ничего не пишет; путь команды абсолютный.
- Вьюер: логика ячеек и координат таймлайна (функция ход × вид, лесенка) вынесена в чистые
  функции и проверяется по данным через существующий приём (тесты сервера отдают HTML и проверяют
  наличие ключей); вид — скриншотами через Playwright в финальном ревью.

## Чего не делаем

- Фоновый форк сессии (`claude -p --resume`) — отвергнут в пользу хука: дороже и не нужен, пока
  хук работает.
- Другие среды, кроме Claude Code и Codex.
- Раскладку графа, канвас, сохранённые позиции (U10).
- Отдельный тип «ждёт пользователя / ждёт агента» у открытых: это выражается `triage` и фразой в
  `why`.
- Настройку порогов через CLI: только `.aang/config.json`.

## Риски

- **Модель не выполнит пинок.** `Stop`-продолжение — инструкция, не принуждение. Смягчение:
  причина сформулирована как команда, скилл разрешён к вызову моделью, повторный пинок придёт с
  ростом транскрипта. Проверяется прогоном в живой сессии обеих сред; в шапке вьюера виден
  «сигнал N минут назад» против «покрыто до N из M», так что застой заметен.
- **Пинок в неудачный момент** (посреди долгой задачи). Обновление карты занимает один ход и
  только удлиняет его; пользователь может поднять `nudge_turns` в `.aang/config.json`.
- **Codex меняет формат транскрипта.** Адаптер завязан на `session_meta` и `item_completed`
  — два имени, оба в фикстуре; поломка проявится как «транскрипт пуст» в `check`, не как тихая
  ложь.
- **Ложный дейксис.** «d1» в промпте о чём-то другом подмешает узел d1. Ограничено существующими
  id и пятью узлами; если окажется шумно — переход на форму с префиксом (`@d1`), это одна
  регулярка.
- **`decided_by` без слов пользователя.** Модель будет писать `user` по короткому «ок».
  Замечание в `check` и во вьюере показывает это, не запрещает.
- **Разросшийся `ui/index.html`** (1464 строки сегодня). Таймлайн, мини-граф, ячейки и SSE —
  ещё ~600. План должен вынести чистую логику (ячейки, координаты, окрестность) в отдельный
  `ui/model.js`, который сервер отдаёт рядом с `index.html`; вид остаётся в `index.html`.
