# Живой замер свежести и экономики наблюдателя (Q.2, Q.3)

Статус: отчёт по пунктам Q.2 и Q.3 плана (`docs/plan/mvp.md`). Это не ADR: настройки по умолчанию и ADR-0007 не меняются, решения принимает владелец, вопросы к нему собраны в разделе 2.

Даты: записи и замеры — 2026-10-07, разметка и отчёт — 2026-10-08. Ветка — `feat/q2q3-live` (PR #163). Измеренная сборка описана в разделе 8.

## 0. Область, версии, метод

Решение владельца от 2026-10-07: живые замеры умеренные.

- Фиксированный профиль нагрузки, порядка пары часов активной работы на рантайм: Claude с Claude-наблюдателем и Codex с Codex-наблюдателем.
- Исчерпание лимита подписки и деградация при отказе проверяются только на поддельном CLI.
- Живые сессии идут во временном тестовом проекте, пользовательские конфиги не меняются, одновременно работает не больше одного живого решателя, всё обезличено.

**Версии и среда:**

- macOS 27.0.1 (Darwin 27.0.0), Apple M4 Pro, 12 ядер, arm64; Node 26.10.0. Машина не выделенная: параллельно работали другие сессии разработки.
- Claude Code из нативного установщика, подписка. Решатель — 2.1.292 (запись `mdlinks` — 2.1.293), наблюдатель — закреплённый бинарь 2.1.293. Модель решателя и наблюдателя — `claude-opus-5-5`.
- `codex-cli 0.160.0` из Homebrew, вход через ChatGPT. Модель решателя и наблюдателя — `gpt-6.1-sol`. Effort наблюдателя — умолчание CLI, у этой модели это `low`.

**Нагрузка.** Четыре задачи по 12 ходов в одной сессии решателя (`docs/research/samples/q2-live/tasks.mjs`):

| Задача | Что делает решатель |
| --- | --- |
| `ledger` | библиотека учёта и CLI по SPEC.md: план, разбор CSV, балансы, вопрос пользователю о способе округления, конвертация, ревью субагентом, CLI, сжатие контекста, экспорт, смена требований (целые центы), два субагента параллельно, README и коммит, итоговая проверка |
| `logstats` | анализ журналов: починка падающих тестов, план, агрегаты с перцентилями, генератор большого журнала и замер, CLI, вопрос о формате отчёта, HTML-отчёт, ревью, сжатие, потоковое чтение, документация двумя субагентами, коммит |
| `kvstore` | хранилище ключей с журналом: план, журнал и восстановление, обрыв строки, вопрос о `fsync`, сжатие со снимком, пакеты, ревью, CLI, сжатие контекста, смена требований (TTL), бенчмарк и случайные тесты двумя субагентами, коммит |
| `mdlinks` | проверка ссылок Markdown: разбор существующих документов, план, извлечение ссылок, проверка файлов и якорей, вопрос о регистре якорей, отчёт, ревью, сжатие, `--fix`, смена требований (JSON), документация двумя субагентами, коммит |

Каждая сессия записана рекордером `tools/record` из модуля `claude-workload.mjs` или `codex-workload.mjs`:

- **Claude** — `claude -p` в режиме stream-json через хост рекордера; каждый ход — отдельный запуск с `--resume` той же сессии.
  - Хост одобряет команды вне списка разрешённых через 2,5 с и отвечает на `AskUserQuestion` первым вариантом через 15 с.
  - Настройки, hooks, плагины и MCP владельца не загружаются (`--setting-sources project,local`, `--strict-mcp-config`), сеть решателя (WebFetch, WebSearch) запрещена.
- **Codex** — `codex exec` в штатном `CODEX_HOME` с `--ignore-user-config`, без hooks и плагинов владельца, в песочнице `workspace-write`; каждый ход — `codex exec resume` того же треда.
  - `codex exec` не умеет спрашивать пользователя, поэтому ответ на вопрос хода дан в его тексте.
  - Сжатие вызвано низким порогом `model_auto_compact_token_limit` на одном ходе.
- Между ходами — паузы 20–60 с, как у читающего пользователя.

Записи обезличены рекордером и проверены его верификатором. Верификатор отклонил запись `mdlinks` для Codex («JSON with duplicate keys, which can hide private data»), поэтому в замере Codex три записи. В репозиторий записи не входят (около 40 МБ); их идентифицируют SHA-256-дайджесты в зафиксированных профилях (раздел 8).

**Профили нагрузки** зафиксированы до замеров (`tools/freshness fix`), окно замера — 120 с, масштаб времени — 1. В каждой записи три вопроса в чат на 30, 60 и 95 % её длительности:

1. «Что сейчас делает прогон и что осталось сделать по плану?»
2. «Какие тесты падали за прогон и чем это закончилось?»
3. «Нужно ли сейчас моё вмешательство? Если да, то где.»

| Замер | Наблюдатель | Записи и старт | Параллельность |
| --- | --- | --- | --- |
| `claude` | effort по умолчанию | полоса 1: `ledger` (0 с), `kvstore` (1408 с); полоса 2: `logstats` (300 с), `mdlinks` (1618 с) | до двух прогонов одновременно |
| `claude-low` | effort `low` | `logstats` (0 с), `mdlinks` (1318 с) | без параллельности |
| `codex` | effort по умолчанию (`low`) | полоса 1: `ledger` (0 с), `kvstore` (1531 с); полоса 2: `logstats` (300 с) | до двух прогонов одновременно |

Замер `claude-low` добавлен после основного, чтобы сравнить effort на тех же записях `logstats` и `mdlinks`.

**Контрольные события.** Рекордер ставит контрольное событие на каждый значимый шаг хода:

- запись PLAN.md;
- последний прогон тестов;
- ответ на вопрос;
- завершение субагента;
- коммит;
- конец хода.

Предикаты добавлены в манифесты до фиксации профиля (`markup.mjs`):

- после записи PLAN.md — на карте есть этапы для всех основных разделов плана;
- после прогона тестов этапа — этап выполнен или его критерий подтверждён;
- после конца хода — этап хода выполнен;
- после смены требований — появился этап для нового требования.

Остальные события оценивает разметчик по описанию ожидания (раздел 4.1).

**Обозначения:** **Э** — наблюдали в замере; **О** — оценка по замеру и правилам ADR-0007.

## 2. Вопросы владельцу

До решений действуют текущие настройки и ADR-0007: effort не задан, ориентиры — 30 и около 40 с, бюджет не ограничен.

1. **Ориентир и effort Claude-наблюдателя** (решения 3, 11 и 12 ADR-0007). Варианты:
   - а) effort `low` по умолчанию (`observer.effort.claude: "low"`) и ориентир 30 с;
   - б) effort по умолчанию CLI и ориентир около 60 с.

   Рекомендация — а):
   - на тех же записях p95 выполненных ожиданий — 29,7 с, без ожиданий плана — 22,9 с;
   - расход на прогон на 6 % ниже;
   - при effort по умолчанию p95 — 51–57 с.

   Перед окончательным закреплением стоит повторить `low` с двумя параллельными прогонами: это около часа подписки.
2. **Ориентир Codex.** Подтвердить около 40 с (решение 11): p95 26,4 с, все выполненные ожидания в пределах 40 с. Сужать до 30 с по одному замеру на трёх записях не рекомендую: максимум — 31,5 с. Effort Codex оставить умолчанием CLI (`low`).
3. **Бюджет токенов по умолчанию** (решение 13). Варианты:
   - а) оставить `budgetTokensPerHour: null`;
   - б) задать предохранитель около 12 млн токенов в час на демон.

   Рекомендация — а):
   - бюджет считает все токены вызовов наблюдателя и проб за скользящий час, по всем backend вместе;
   - пик замера Claude — 7,9 млн токенов за час на двух параллельных прогонах. Любой бюджет ниже этого ломает свежесть: порции идут раз в 60 с, состояние становится `lagging`;
   - сверху расход и так ограничен двумя одновременными вызовами наблюдателя на демон. Это около 14 млн токенов в час для Claude при effort по умолчанию (О: 2 × 3600 с / 13 с × 25 тыс. токенов);
   - снижать стоит стоимость вызова (вопрос 5), а не частоту.
4. **Отражение плана** (нарушения раздела 4.5).
   - а) Промпт наблюдателя: явный план (PLAN.md, список задач) сразу раскладывается в запланированные этапы. Это отдельный PR в `observer`, после него — повторный замер. Рекомендую: без этого карта 9–17 минут не показывает план, а это одна из основных её функций.
   - б) Требование «бриф называет цель прогона» убрать из будущей разметки. Цель уже есть в модели правилом: `run.goal` из первого сообщения, ADR-0006. Бриф у обоих наблюдателей описывает текущее состояние. Рекомендую б), если UI показывает `run.goal` рядом с брифом; иначе — дополнить промпт.
5. **Кэш Claude-наблюдателя** (О, раздел 6).
   - Каждый вызов читает из кэша только неизменную часть, ровно 9 029 токенов.
   - Остальной вход (p50 13,8 тыс. токенов) он пишет в кэш, который следующий вызов не читает.
   - Предлагаю отдельно исследовать вызов без записи изменяемой части в кэш. Ожидаемая экономия — большая часть из 59 % токенов наблюдателя; деньги без собственной таблицы цен (ADR-0009) не оценить.
6. **Записи нагрузки** (около 40 МБ, 7 записей): хранить вне репозитория у владельца (сейчас так) или вынести отдельным PR без кода, как эталонные сессии (ADR-0010). Рекомендую вне репозитория: в отчёте их идентифицируют дайджесты.

## 3. Дефекты, найденные замером

Живой замер упёрся в четыре дефекта, без исправления которых Q.2 и Q.3 не измерить. Все исправлены.

1. **Допуск Claude-наблюдателя не проходил на настоящем CLI** — PR #158, смержен 2026-10-08 вместе с новой формулировкой ADR-0007.
   - Claude Code 2.1.289–2.1.293 на macOS запускает command-hook в собственной группе процессов: у контрольного hook допуска `pid` 94382, `ppid` 94369 (сам `claude`), `pgid` 94382.
   - Проверка групп процессов (решение 10 ADR-0007) видела этот `node` вне группы вызова, и допуск не проходил: backend — `disabled: isolation` с причиной «CLI descendant left its process group: node».
   - Исправление повторяет исключение для контрольного hook Codex из #136: группа, лидер которой записал свой `pid` в метку, нарушением не считается.
2. **Ответы Claude-наблюдателя отклонялись схемой** — PR #162, смержен 2026-10-08.
   - В операции `stage.depends` поле `via` — id версии артефакта или `null`. Claude 2.1.293 писал туда путь (`SPEC.md`, `PLAN.md`), и демон отклонял ответ целиком.
   - В первые 10 минут первой попытки замера отклонено 9 ответов из 10, все из-за этого поля. Эта попытка остановлена.
   - Промпт теперь объясняет `via`, а причина отклонения по схеме называет поле и доходит до `previous_attempt`.
   - В замерах этого отчёта отклонений по `via` нет. Отклонения всё же были, по другим причинам:
     - `claude` — 3 из 316: факт вне порции дважды, критерий плана без факта плана один раз;
     - `claude-low` — 5 из 175: карточка не совпадает с цитатой четыре раза, факт вне порции один раз;
     - `codex` — 1 из 213: карточка.
3. **Журнал чата был пуст** (этот PR). Демон создавал чат без журнала, поэтому вызовы чата не попадали в `observer_calls`, а журнал «чат» в `aang usage` и на панели расхода всегда был пуст. Теперь каждый вызов CLI вопроса, включая дозапрос, пишется в журнал.
4. **Рекордер не записывал длинные сессии** (этот PR).
   - Каждые 25 мс скан перечитывал все файлы источников целиком, и на часовой сессии очередь сканов росла без ограничения.
   - Теперь скан пропускает неизменные файлы, дочитывает растущий JSONL и не ставится в очередь за идущим сканом.
   - Изменённый без роста или заменённый файл читается целиком. Скан на границе команды по-прежнему сверяет весь захваченный префикс.

Мелкое:

- `/api/runs/:run/observer-calls` отдаёт `error: null`, `cli_version: null` и `model: null` у каждого вызова, хотя класс ошибки хранится. Инструмент берёт класс ошибки из хранилища после остановки демона.
- Отменённый при остановке вызов записывается как `failed` без класса и сообщения.

Операционное: Claude Code обновил себя с 2.1.292 до 2.1.293 между записями — его обновляли другие сессии владельца. Чтобы версия наблюдателя не сменилась посреди замера, в профилях закреплён путь к бинарю 2.1.293.

## 4. Свежесть (Q.2)

### 4.1. Метод оценки

- **Предикат** проверяет инструмент: первая версия модели после события, в которой предикат выполнен. Предикат, выполненный уже до события, — дефект разметки, событие в статистику не входит.
- **Описание** оценивает разметчик по полному состоянию карты.
  - Кандидаты — все версии прогона в окне 120 с после события. `state.mjs` печатает полное состояние карты до события и изменения каждого кандидата, а с `--at` — полное состояние выбранного кандидата.
  - Вердикт — первый кандидат, в котором выполнена каждая часть описания, включая часть до двоеточия: смысл, а не формулировка.
  - Если описание выполнено уже до события, вердикт — «выполнено до события».
  - Если описание противоречит тому, что сделала сессия, вердикт — «не соответствует записи». Это решается по самой записи, одинаково для всех замеров этой записи.
  - Оба таких случая — дефекты разметки, в p95 они не входят, как и предикат, выполненный до события.
- **Основание.** Каждый вердикт имеет основание: версия, сущности и их состояния, почему предыдущий кандидат не подходит. Вердикты лежат в `results/<замер>/verdicts.json`, применённая разметка — в `annotations.json`.
- **Эвристики.** Прежние вердикты по совпадению названий этапов отброшены. Разметку выполнили четыре отдельные сессии Claude Opus по общему регламенту (правила — этот раздел), каждая — свои записи. Пример расхождения с эвристикой — `ledger:rounding-answered`:
  - эвристика выбрала v21 через 0,9 с, где наблюдатель только создал этап «спросить пользователя», а вопрос ещё открыт;

- **Неоднозначные описания и принятое прочтение:**
  - «running» в ожидании о текущей работе выполняется и уже завершённым шагом: карта опережает, а не отстаёт;
  - «every stage of the plan» — этапы PLAN.md;

## 5. Исчерпание лимита и деградация (поддельный CLI)

Лимиты владельца не расходовались: сбои воспроизведены поддельным `claude` из `@aang/testkit` (`fake-observer.mjs`).

- Профиль: записи `ledger` и `logstats` со стартом через 60 с, масштаб времени 0,25 (в четыре раза быстрее записи), окно 120 с, те же вопросы в чат.
- Поддельный наблюдатель отвечает мгновенно скриптом `map` и именует этапы по-своему. Поэтому предикаты разметки на нём не выполняются, и задержки этих прогонов не показательны.
- Смотрятся состояния наблюдателя, очередь фактов, версии карты и вызовы (Э, `degradation.mjs`, итоги — `results/degradation-limit.json` и `results/degradation-failures.json`).

| Сценарий | Сбой | Состояние и длительность | Пик очереди, фактов | Версии карты во время сбоя | Восстановление |
| --- | --- | --- | --- | --- | --- |
| лимит подписки | после 12 вызовов — ответ «лимит» со временем сброса через 4 минуты после установки | `unavailable:limit` 145 с в обоих прогонах, 32 % времени замера | 442 и 532 | правила — 2, наблюдатель — 0 | в момент сброса одна проба на синтетическом входе, затем обычные порции; очередь первого прогона опустилась до 30 фактов за 241 с, второго — не опустилась до конца замера |
| сбои сети | после 12 вызовов — пять ответов подряд с ошибкой сети | `backoff` 312 и 313 с: паузы 10, 20, 40, 80 и 160 с, 68 % времени | 749 и 913 | правила — 12 и 4, наблюдатель — по 1 (успешный ответ между сбоями) | факты старше 5 минут ушли в сжатую сводку догоняющего режима (`lagging: backlog` на полсекунды), очередь сразу пуста |

- **Сбор не останавливается.** Факты копятся в очереди прогона, правила продолжают менять карту (явные запросы, состояние выполнения), наблюдатель вызовов не делает. Состояния `unavailable: limit` и `backoff` видны в UI с первого отказа.
- **Лимит.** Демон не тратит попытки порции и не повторяет вызовы до времени сброса, которое сообщил CLI.
  - После сброса — одна проба (в журнале `probe`) и возврат к работе.
  - За 145 с отказа отставание не дошло до порога догоняющего режима (5 минут), поэтому очередь разбиралась обычными порциями: не больше 30 фактов на вызов и не чаще раза в 10 с.
  - В ускоренном вчетверо профиле факты приходили быстрее, и второй прогон не догнал очередь до конца замера. В реальном времени поток фактов вчетверо реже.
- **Сбои сети** укладываются в правила ADR-0007: пауза удваивается с 10 с. Отставание больше 5 минут включает догоняющий режим: ранние факты уходят наблюдателю сводкой, и карта помечается как восстановленная с пониженной детализацией.
- **Чат** во время сбоя наблюдателя отвечал: у поддельного CLI ответы чата не зависят от сценария отказа. Настоящий лимит подписки отклонил бы и чат — это поддельным CLI не проверить.
- **Свежесть во время сбоя.** Нарушения неизбежны: ожидание не выполняется, пока наблюдатель недоступен. Ориентир RFC §8 относится к работе без отказа LLM; во время отказа UI показывает возраст смысловой модели.

  - Вход без кэша у наблюдателя — 0,43–0,58 млн, у решателя — 0,15–0,21 млн: в 2,7–3,1 раза больше.
- Деньги решателя транскрипты не сообщают, поэтому сравнение — только по видам токенов.

**Разовые затраты:**

- **Допуск Claude** на каждую новую версию CLI (`admission-cost.mjs`, Э): 2 вызова по 3,5–3,7 с, 20 150 токенов, $0,019. Claude Code выходит почти ежедневно, то есть около $0,02 в день.
- **Допуск Codex** отдельно не мерился: те же два вызова, расход в журнал вызовов не попадает.
- **Проба после сброса лимита** — один короткий вызов (раздел 5).
- **Запись неизменной части входа в часовой кэш** — около 9 тыс. токенов раз в час простоя.
- Регулярные затраты на два порядка больше разовых.

**Час по U.1.** Учёт расхода демона (U.1) считает активными календарные часы с активностью решателя, их здесь 2 на каждый замер. Поэтому его «на активный час» вдвое меньше измеренного: например, у Claude-наблюдателя $23,23 против $45,67. Это следствие определения, а не ошибка учёта.

## 7. Как воспроизвести

Сборка — `pnpm build`.

**Записи нагрузки.** Живые решатели, по одной за раз. Claude — штатный `~/.claude` владельца без его настроек, Codex — штатный `CODEX_HOME` без hooks и плагинов:

```sh
F=fixtures/workloads
for task in ledger logstats kvstore mdlinks; do
  AANG_Q2_TASK=$task AANG_Q2_FIXTURES=$F node tools/record/dist/main.js record $PWD/docs/research/samples/q2-live/claude-workload.mjs
done
for task in ledger logstats kvstore mdlinks; do
  AANG_Q2_TASK=$task AANG_Q2_FIXTURES=$F node tools/record/dist/main.js record $PWD/docs/research/samples/q2-live/codex-workload.mjs
done
node docs/research/samples/q2-live/markup.mjs $F
```

**Профили, замеры и разметка.** Наблюдатель — закреплённый бинарь. Записи ищутся по каталогам версий, так что смешанные 2.1.292 и 2.1.293 находятся сами. Эти команды дают байт в байт зафиксированные профили этого отчёта (до обезличивания пути CLI):

```sh
D=docs/research/samples/q2-live
CLAUDE="$HOME/.local/share/claude/versions/2.1.293"
CODEX=/opt/homebrew/Caskroom/codex/0.160.0/bin/codex
node $D/profile.mjs --runtime claude --fixtures $F --surface claude_cli --cli "$CLAUDE" --out claude.json
node $D/profile.mjs --runtime claude --fixtures $F --surface claude_cli --cli "$CLAUDE" --effort low --name claude-workload-low --lanes logstats,mdlinks --out claude-low.json
node $D/profile.mjs --runtime codex --fixtures $F --surface codex_exec --cli "$CODEX" --lanes 'ledger,kvstore;logstats' --out codex.json
for m in claude claude-low codex; do
  node tools/freshness/dist/main.js fix $m.json measure-$m --fixtures $F
  node tools/freshness/dist/main.js run measure-$m --fixtures $F
done
node $D/annotate.mjs measure-claude
node $D/state.mjs measure-claude workload-ledger:rounding-answered --at 5
node $D/annotate.mjs measure-claude --verdicts verdicts.json
node tools/freshness/dist/main.js report measure-claude
```

**Как работает разметка:**

- `annotate.mjs` без `--verdicts` печатает события и кандидатов;
- `state.mjs` печатает полное состояние карты, ему нужно хранилище замера;
- `annotate.mjs --verdicts` применяет вердикты: у каждого события должен быть вердикт с основанием `reason`;
- `candidate` — индекс кандидата или `null`, флаги `held_before` и `mismatch` отмечают дефекты разметки.

**Пересчёт по сохранённым данным**, без живого прогона:

```sh
for m in claude claude-low codex; do
  node $D/annotate.mjs $D/results/$m --verdicts $D/results/$m/verdicts.json
  node tools/freshness/dist/main.js report $D/results/$m
done
node $D/compare.mjs $D/results/claude $D/results/claude-low
node $D/analyze.mjs $D/results/claude
```

**Прочее:**

- Разовая стоимость допуска Claude — `node $D/admission-cost.mjs --cli "$CLAUDE"`.
- Деградация на поддельном CLI:
  1. `node $D/fake-observer.mjs limit <каталог> --before 12 --limit-seconds 240` или `node $D/fake-observer.mjs failures <каталог> --before 12 --failures 5` печатает путь поддельного `claude` для `observer.claude.cli`;
  2. профиль — записи `ledger` (0 с) и `logstats` (60 с), `time_scale` 0,25, вопросы на 30, 60 и 95 % ускоренной длительности;
  3. затем `node $D/degradation.mjs <каталог замера>`.
